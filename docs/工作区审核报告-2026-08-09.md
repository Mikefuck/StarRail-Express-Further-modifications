## 已确认并处理的问题

### 1. 任务 NBT 恢复绕过运行时不变量

`TaskInstance.fromNbt` 原先直接写入 `maxProgress` 和 `elapsedTicks`，损坏或旧版 NBT 可恢复出 `maxProgress <= 0`、负计时，或 `failed=true` 但 `fulfilled=false` 的矛盾状态。现在恢复路径复用 `setMaxProgress`、钳制负计时，并归一化失败状态。

### 2. 自定义任务方块包缺少总条目上限

`CustomTaskBlockPayload` 只限制了单坐标的类型数，没有限制坐标总数。损坏或恶意数据可造成过量分配。现在加入 65,536 条硬上限，并把旧常量重命名为实际语义 `MAX_TYPE_IDS_PER_ENTRY`。

### 3. Gradle 10 兼容警告

`settings.gradle` 和 `build.gradle` 共 8 处 Maven 仓库仍使用已弃用的 Groovy space-assignment 语法。现已改为 `url = ...`；`gradlew help --warning-mode all` 不再报告这些弃用项。

### 4. 工作区说明与实际构建不一致

旧 README/教程仍使用已删除的 `HabiTask*` API、旧配置路径和旧颜色参数；项目 `AGENTS.md` 还记录错误的 Loom 版本、测试状态和发布目录。现已统一到当前代码：

- API：`TaskRegistry`、`TaskDefinition`、`TaskInstance`、`TaskCategory`。
- 配置：`config/habitrain_core.json`。
- 构建产物：`build/release/habitrain_core-2.0.1-restored.jar`。
- 交付：完整构建后复制到 `../临时/`。
- 本地 `.bak` 依赖备份加入忽略规则，文件本身保留。

### 5. 英文语言包缺项

`en_us.json` 比 `zh_cn.json` 少 9 个本模组键，英文客户端会显示原始翻译键。现已补齐，两个语言包各 255 个键且集合一致。

### 6. 当前对局结束过渡改动缺少测试

已核对上游 `SRERole#getRoleType()` 契约：1=好人、2/3=两类中立、4=杀手、5=警长阵营，与当前武器分配逻辑一致。新增测试覆盖 MVP 列表最多 4 人、防御性快照和非法角色类型回退。

## 仍需关注的风险

### 中：Mixin 漂移可能静默降级

公共/客户端两份主要 Mixin 配置使用 `required: false`。这能提高不同 SRE 版本下的启动容错，但上游方法签名变化时，部分核心功能可能只记录日志后失效。发布前应在目标 SRE JAR 上检查启动日志并完成一局谋杀、修机和停电模式。

最终 remap 还明确提示 `LightningDraftState` 与 `SingleSelectDraftState` 中不存在 `lambda$initializeRolePool$*` 目标；这两处使用通配 lambda 选择器，必须通过目标 SRE 版本的启动日志和 rotation 模式实测确认注入是否仍生效。

### 中：自动化测试覆盖仍有限

当前 46,000 余行主源码只有 15 个单元测试，重点覆盖 API 值对象和角色覆盖定义；网络编解码往返、配置迁移、投票状态机、停电胜负和 GameMode 生命周期仍缺少自动化测试。

### 中：配置写盘不是原子替换

`ConfigStore.save` 直接通过 `FileOutputStream` 覆盖主配置。进程在写入中途终止时可能留下半写 JSON，随后加载逻辑会重建默认配置。后续宜改为同目录临时文件写入、flush 后原子替换，并保留损坏文件供恢复。

### 低：存在未绑定资源的已注册音效

`betel_nut_eat`、`betel_nut_get`、`look_my_eyes` 注册了 `SoundEvent`，但当前 `sounds.json` 和资源目录没有对应音频；项目内部目前也没有播放这些常量。若下游调用会静音，应在取得合法音频资源后补齐，或在下一次破坏性 API 版本中移除。

### 低：仓库内固定二进制依赖体积较大

`libs/` 约 205.57 MiB，包含多个 JAR、反编译辅助文件和一个已跟踪 `.bak`。这些文件当前是可复现构建输入，不能在没有依赖来源/校验和方案时直接删除或取消跟踪；本次仅忽略新的本地 `.bak` 备份。
