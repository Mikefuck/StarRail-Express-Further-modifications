## 安全的执行入口

所有 Java 验证使用项目 wrapper 和 `--no-daemon`；推荐用 `verification/Invoke-S0Gradle.ps1`，它建立 ASCII 路径别名、记录本次进程并在 finally 等待子进程退出。
日志名必须唯一，防止覆盖证据。不要把默认 `run/` 当成本次隔离目录。

```powershell
.\verification\Invoke-S0Gradle.ps1 -Name acceptance-build -GradleArguments @('build')
.\verification\Invoke-S0Gradle.ps1 -Name acceptance-server -GradleArguments @('runS0Server')
.\verification\Invoke-S0Gradle.ps1 -Name acceptance-client -GradleArguments @('runS0Client')
```

现有 `run/eula.txt` 为 false，隔离目录也保留 false。当前没有安装新的生产 Fabric 启动器、没有替用户接受 EULA。
正式启动需用户按其选择完成 EULA 和启动器准备。服务器只绑定 127.0.0.1，禁用 RCON/query；同一端口的多套测试按顺序运行。
完整服务端启动、语音网络行为及图形渲染不能用 pre-EULA 退出或 JUnit 结果代替。

## 生产安全 Mixin 的证据入口

在生产启动器的 JVM 参数中加入 `mixin-jvm-args.txt` 的参数：

```text
-Dmixin.debug.export=true
-Dmixin.debug.export.decompile=false
-Dmixin.debug.verbose=true
```

这些参数依据 [Mixin 官方说明](https://github.com/SpongePowered/Mixin/wiki/Mixin-Java-System-Properties)。
`-Dmixin.debug.countInjections=true` 只作额外诊断：它会把第三方可选注入的 expect 也提升为错误，本次会触发 Carpet 的零命中断言，不能将该模式当成常规启动基线。
导出的是应用 Mixin 后的类；导出目录在运行目录的 `.mixin.out/class/`。
依次触发普通击杀、休息区攻击/被攻击/切换模式、维修开局/准备/选角/重置和玩家加入。
保留当前生产 JAR、SRE JAR 摘要、启动日志、场景步骤及 `.mixin.out`，再运行：

```powershell
.\verification\Invoke-S0Gradle.ps1 -Name production-mixin-evidence -GradleArguments @('verifyProductionMixins','-Ps0RuntimeDir=H:/.verification/s0-20261106/runtime/production-minimal')
```

核验器直接读取当前重映射生产 JAR 的目标类和处理器签名，在导出的转换后类中查找。缺导出、缺处理器、运行目录不含当前 JAR 都是失败。
它检查 guards/rest_area 的处理器是否进入转换后类；玩法效果、其他模组覆盖、客户端 Mixin 和注入调用是否位于正确业务路径仍需场景验收。
客户端/常规配置的全部目标方法另由 RoleFixMixinCompatibilityTest 静态预检，不能因此宣告生产命中。
