# 普通谋杀模式开局列车环境音

## 原因

`SceneMotionSettings` 默认启用场景系统；`SceneProfile` 默认不启用背景，但旧版
`SceneSoundSettings` 默认启用 `habitrain_core:moving_scene_outside`。
`SceneRuntimeCoordinator.onMatchStarted` 允许独立的地图声音运行，不要求启用背景，
因此普通谋杀模式开局也会下发活动场景状态。客户端收到状态后循环播放该声音。
该声音实际引用 `minecraft:entity.minecart.riding`，音量 0.7、音调 1.0。

附加场景音只随状态更新启动。将总音量设为 0 会清除正在播放的声音，恢复音量后
不会立即重新启动它。这与报告的现象吻合；仍需实际普通谋杀对局确认听到的就是此音源。

此外，实际 SRE 4.3.0 依赖中 `MyBackgroundAmbience.tryStarting` 首次创建实例时
跳过播放条件检查，且 `MyBackgroundAmbientLoop` 在首次 tick 前直接使用目标音量。
原有开局补丁只阻止新实例，没有处理此前已启动的循环音。

## 修复

- 附加场景音改为默认关闭，仍可在动态背景配置的默认设置中单独开启。
- 配置版本升级为 4。旧版没有启用主背景或附加背景、且声音仍为默认列车音及默认参数的
  配置会关闭该声音。保留自定义音效参数和已启用背景的显式声音配置。
- 迁移只执行一次，之后手动重新开启默认列车音会正常保存。
- SRE 场景音首次启动也检查播放条件；开局过渡或维修时停止旧实例，新实例从静音淡入。

## 验证

新增回归测试覆盖新地图默认静音、旧配置迁移、输入配置不被修改、迁移幂等性、
主背景与附加背景的声音保留、自定义声音保留、用户重新开启声音，以及开局循环音清理。
兼容性测试检查实际 SRE 依赖的 Mixin 目标方法和字段。

游戏内复测：更新服务端和客户端的 core jar，重启后开始普通谋杀模式，
不操作音量滑块，检查额外循环列车声是否消失；再连续开启第二局确认。
本次未进行游戏内听音验证。
