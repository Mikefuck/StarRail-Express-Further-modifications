## 2. 项目画像

### 2.1 职责

`habitrain_core` 是星穹列车（StarRailExpress）生态的 **可编辑核心**：

1. **游戏逻辑核心**：停电模式、SRE 谋杀/修机桥接、七宗罪/美德、任务引擎、投票、配置中心、网络同步、Mod Menu、槟榔集成、语音群组等。
2. **公开 API**：任务 / 游戏模式 / 投票 / 角色覆盖 / 道具回收，供附属模组使用。

`onInitialize` 顺序要点：加载配置与菜单门控 → 注册 GameMode（谋杀/修机/停电 + 原版模式桥）→ 角色/覆盖/修饰符 → 网络/命令/生命周期/C2S → 内置与停电任务 → 音效 → **强制开启槟榔成瘾系统**。

**注册表冻结**（`LifecycleEventsRegistrar`，`SERVER_STARTED`）：

- `TaskRegistry.freeze()`
- `GameModeRegistry.freeze()`
- 角色覆盖引擎按真实配置重建

这与工作区记忆一致：Fabric `depends` **不保证** `onInitialize` 顺序，故冻结放在服务端启动后、所有 entrypoint 完成之后。

## 4. 网络与 C2S 安全

### 4.1 注册表

`NetworkRegistrar.init()` 依次注册 30 个 payload 类型（含任务/配置/光影、停电电话与商店、选项/地图投票、结算过渡、贪婪交易、淘汰休息区、菜单门控、修机同步、自定义任务方块等）。

### 4.2 C2S 抽查（`C2SReceiverRegistrar`）

| Payload | 校验 |
|---------|------|
| `ConfigUpdatePayload` | 主线程执行；`hasPermissions(4)`；专用服 + MenuGate 未授权则拒绝；`mergeFromJsonString` + save + 广播 |
| `ConfigUpdatePayload` 编解码 | `MAX_JSON_LENGTH = 1_048_576`，超限 `DecoderException` |
| `ShaderInfoPayload` | 白名单启用时校验包名，不在名单则 disconnect |
| `BlackoutHirePolicePayload` | `BlackoutPoliceHireService.tryHire` 服务端逻辑 |
| `BlackoutTaskShopBuyPayload` | 目录查找 + `BlackoutTaskShopService.tryPurchase`（模式/存活/阵营/余额等） |
| `BlackoutVoteCastPayload` / `OptionVoteCastPayload` | 投票 manager；id 不匹配 no-op |
| `GreedTradeAction/Select` | `GreedTradeManager` 会话校验 |

`CustomTaskBlockPayload`：**S2C**；解码 `MAX_ENTRIES = 65_536`、`MAX_TYPE_IDS_PER_ENTRY = 64`（今日已加总条目上限）。

### 4.3 已确认：权威写缺少距离 / 交互门闩（本轮不修）

这些路径**都有**模式/角色/余额等业务校验，**不是**裸发奖；缺口是客户端可在无准星距离或未与电话交互时触发服务端状态变更。

| # | 路径 | 证据 | 影响 |
|---|------|------|------|
| 1 | `GreedTradeSelectPayload` → `GreedTradeManager.openSelectedTrade` | `openSelectedTrade` 校验贪婪角色/袋/存活，**无** `TRADE_RANGE`；对比 `useTradeSkill` 走 `resolveTarget` 有距离 | 可对同维任意在线玩家远程打开交易会话（提交仍校验余额/物品） |
| 2 | `BlackoutTaskShopBuyPayload` → `tryPurchase` | 校验模式/存活/阵营/余额/阶段，**无**与红色电话的距离或 open 会话 | 对局中可远程扣金并派发任务/临时电源 |
| 3 | `BlackoutHirePolicePayload` → `tryHire` | 校验对局/存活/余额等，**无**电话交互证明 | 可远程扣金触发雇警逻辑 |

**另（正确性）**：`HabiTrainCore` 全服只 `new BlackoutMode()` 一次，实例字段 `currentLevel`/`gameEnded` 等与 `GameModeRegistry` 按维度持有**同一引用**冲突——多维度并行开停电时会互相覆盖（常见单 overworld 部署下多为 latent）。

**结论**：无“无限钱/无条件 kill”裸洞；配置 OP+门控合格。发布前若收紧玩法安全，应优先为 #1–#3 补距离/交互门闩，并评估 BlackoutMode 每维实例化。
