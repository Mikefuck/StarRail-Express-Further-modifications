**崩溃根因与修复**

16:45:44，Netty 网络线程开始断线清理；上游 `SREClient` 的 DISCONNECT 回调将 `gameComponent`、`trainComponent` 等静态缓存清空。渲染线程仍在绘制世界中的车轮，`WheelBlockEntityRenderer.render` 第 132 行直接调用 `SREClient.trainComponent.getTime()`，引发空指针。

崩溃位置是 `trainmurdermystery:wheel`，坐标 `(-4852, 49, 247)`。它不是懒惰技能处理或暴怒破门调用抛出的异常。此前语音超时、连接重置和连接拒绝属于另一个网络问题；仅凭这份客户端报告不能确定服务端断开的根因。

在 API 模组内新增两项客户端 Mixin，上游 DLC 文件没有修改：

- `WheelRenderDisconnectMixin`：在实际的 `getTime()` 调用点检查已经捕获的接收对象，缓存为空时返回 0。
- `SREClientTrainStateMixin`：保护 `getTrainSpeed()` 和 `isTrainMoving()` 内部的速度、对局状态读取，覆盖车轮、场景和环境效果共享的查询入口。

保护放在实际调用点，避免“方法开头检查不为空，随后网络线程又清空缓存”的检查与使用间隙。组件仍有效时继续调用原方法；没有捕获并吞掉整个渲染流程的异常。
