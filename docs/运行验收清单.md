# 运行验收清单

本清单对应 2026-10-13 系统审核 R01–R09，用于保留静态修复与游戏验收的区别。依赖安装先按 [版本与安装依赖](版本与安装依赖.md)；构建、JUnit 与开发启动均不能单独证明固定成品在真实 Fabric 环境中的玩法正确。以下游戏操作尚待真实运行记录。

| 编号 | 验收入口与条件 | 必须记录的结果 |
|---|---|---|
| R01 强制就绪名单 | 普通开局；双阶段投票后普通开局；STARTING/INITIATING 断线重连；集成服同 JVM 换世界 | 记录 roundId/维度与名单建立、开局、结束、取消、停服的时点；没有旧世界名单残留 |
| R02 多维度同时对局 | 在 A 维度开始对局后尝试从 B 启动 | 并行支持仍需产品决策；不得以跨维度维修/休息区修复声称已实现独立并行对局 |
| R03 Mixin 实际命中 | 固定 SRE 成品 + 新 Core 客户端/专用服；查看启动日志并执行任务、杀人、结局、休息、维修、场景渲染 | required 配置无失败；逐关键适配入口确认注入实际触发；不能仅凭 compile/build 关闭 |
| R04 扫描开销 | 场景源选区、大地图任务方块索引；在正确服务器世界线程扫描 | 记录体积、过程条目数、加载区块、耗时/服务器 tick；过程预算、取消与进度仍需单独优化验收，不直接后台读世界 |
| R05 状态/Hook/Action 门控 | 大厅禁用→开局；局中禁用→下一局；重新启用 | 记录 live/pending 与状态镜像变化；当前局冻结 hooks/actions 与实时 state gate 的统一策略仍需产品决策 |
| R06 配置副作用负载 | 新配置提交协议连续保存不同字段、重复同 requestId、超频、超预算 | 仅改变模块触发副作用；有限请求预算与可读拒绝；不将永久历史 JSON 去重作为限流 |
| R07 多管理员旧草稿 | A/B 同时打开列表；A 新增后 B 从旧草稿提交 | baseRevision 冲突明确提示；B 的旧整表不静默覆盖 A；收到广播不等于本次请求确认 |
| R08 旧 TaskConfigPayload | 旧辅助包 codec 边界与 round-trip；主链 FullConfigSyncPayload | 标记旧包为仅保留兼容辅助，不把无发送调用的旧包写成主同步故障；以新主链验收配置完整性 |
| R09 光影自报边界 | Iris 包 A 不变，关闭→开启白名单/移除 A；关闭光影、无 Iris、刚切换、断线重连 | 正常客户端按新规则重报/重评；未上报有等待窗口；不声称防止修改客户端伪报 |

R02/R05 的未决产品语义不应阻止其他确定性修复，也不能在这轮修复中擅自扩大为全局多世界架构变更。R10 已升级为 F28，异常断线/停服收尾按 F28 的专用回归与游戏验证记录，不重复计数。

当前工作区具有原始依赖成品与对应缓存，足以准备客户端成品实例；项目 `runClient`/`runServer` 可作开发入口。专用服还有固定 SRE 强制依赖客户端 Mod Menu 的元数据矛盾，详见安装文档。任何依赖绕过方案和实际游戏结果都必须单列，不能写成 Core 构建已经解决。
