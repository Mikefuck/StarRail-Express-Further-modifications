## 本次实现

1. **统计完成后的结算顺序。** MatchEventBridge 在上游 recordWinStats 完成后构造不可变快照，依次派发内部胜者 hook、公开 ROUND_ENDED，最后在 finally 清理角色轮次状态。同一局重复结束不重复派发。Lust/Sloth 的清理从早期 OnGameEnd 移到此清理阶段，修复色欲跟随胜利读取不到魅惑记录的问题。胜者观察期间仍能读取本轮角色状态，观察完成后再重置。服务端停止清理桥接状态。
2. **最终胜者来源统一。** 权威统计后路径直接使用实际 hasWin/didWin，不再合并过期 CustomWinnerPlayers，也不为零胜者重建阵营胜者。MVP 最终缓存使用同一快照。旧 fromEnd 兼容入口保留，不宣称所有旧调用者都已迁移。
3. **翻包任务与缓慢来源。** 删除重复及无条件 removeEffect 释放，所有路径通过 SlownessReapplyManager 的规格释放；保留更强外部缓慢，重复释放幂等。读条绑定任务实例ID，并在开始/持续阶段检查目标区块、距离和视线，防旧实例读条作用于新任务。
4. **模式重入与查询。** 每局使用独立会话UUID，旧 onPreStart/onStart 异常或旧 tick 无法清理、停止、释放回调内新开的同一 GameMode 对象。异步被动查询读取最后一个服务端发布的观察值，避免在外线程访问世界时钟或第三方 isActive；返回值可能滞后或为空。
5. **第三方模式 ID。** SRE 遮罩/协调器判定改为明确内置ID或既有原生代理，不再按名称包含关系误认第三方模式，新增回归验证 repair_kit 等负例。

本次对比起点是任务开始时的 source-before.zip，而非 Git HEAD。12个现有源码/测试文件发生变化（11个生产文件、1个JUnit文件）；未覆盖或回滚此前 S1–S3 未提交修改。完整任务差异：.verification/s4-20261107/changes-vs-task-start.patch。
