# 配置编辑与提交

本合同随 2026-10-13 审核修复版 Core 2.0.24 发布，客户端与服务器应配套更新。配置文件 schema 与网络 protocol=1 分别管理。完整同步仍用于显示服务器权威值；保存使用 delta，收到广播本身不表示某次请求保存成功。

## 草稿与权威状态

本地配置、服务器镜像、页面草稿分别保存。远端客户端和 LAN 客人编辑或关闭页面时不写本机 habitrain_core.json；断线与换服丢弃该连接的草稿并恢复本地快照。集成主机也通过 C2S 提交，由服务器线程验证、写盘、发布新权威配置及执行变化模块的副作用。界面中的开关只修改草稿；小游戏强制应用和场景资产删除发生在服务端成功提交后。

打开页面记录 baseRevision。其他管理员或命令改变权威配置后，旧版本提交返回 CONFLICT，保留草稿；保存栏的“放弃草稿并重载”会用最新镜像替换草稿，再允许编辑。未保存字段不会被普通广播直接覆盖。成功 ACK 到达时，提交之后继续进行的编辑会叠加到新镜像上，防止无关旧字段被误当作下一次修改。

## 请求与响应

ConfigUpdatePayload 的 JSON 包含 protocol、requestId、baseRevision、patch，以及页面 scope 元数据。requestId 是连接内的 UUID，同一编号重传返回原操作结果，不重复副作用；同一编号更换内容被拒绝。每连接只保留最近八条结果；断线清理请求窗口。新编号即使恢复此前使用过的内容，也会根据当前配置重新评估。服务器配置提交间隔至少 250ms，超频有明确拒绝结果。

patch.set 是 JSON-pointer 路径到值的对象，patch.remove 是路径数组。缺省路径保持不变；移除任务奖励字段恢复继承；移除条目删除该条目；数组可用空数组显式清空。null 不用作删除。模式和地图的排序具有语义，纯重排也会传输并保存。

| scope | 服务端允许的修改 |
|---|---|
| FULL_MOD_MENU | Core 配置各模块；OP2，专用服门控开启时还需后台授权 |
| BACKPACK_TASKS | tasks；OP2 |
| BACKPACK_MAP_VOTE | modeMapVote；OP2 |
| ADMIN_SCENE_TOOL | 服务端认可的选定地图 profiles/backgrounds；OP2 |

服务端重新验证 scope、权限、版本和完整候选 schema，写盘成功后才替换权威内存。保存结果区分 NO_CHANGE、SAVED、FAILED、CONFLICT；客户端发送后显示 SUBMITTING，收到匹配 requestId 的 ConfigResultPayload 才显示服务器保存结果。15秒没有确认显示超时并保留草稿。保存已经成功而后续发布/运行刷新失败时，结果明确说明已保存及刷新失败，不声称自动回滚不可逆副作用。

## 数值与网络预算

任务金币奖励必须是32位整数，情绪奖励允许有符号有限浮点数。刷新权重要求有限且非负，0禁用任务；空输入继承默认值。错误输入不部分提交数值或覆盖标记。磁盘和网络候选复用验证器；完整 schema 错误也会尝试有效备份，备份恢复不会覆盖唯一好备份。

所有预算均为 UTF-8 字节数。C2S JSON（包括元数据）上限30000字节，为底层包头留空间；局部操作只发送变化字段。S2C JSON上限1000000字节，给 ACK 其他字段、长度头和底层包头留空间；候选落盘前再次验证可同步大小。超预算返回可读错误，不采用部分应用的分片。大配置只修改一个小任务可以提交，但完整权威配置仍须满足 S2C 预算。

旧完整 JSON 客户端提交会被明确拒绝并要求配套版本；新版客户端未收到带 revision 的协议快照时拒绝保存。旧 TaskConfigPayload 继续保留为辅助兼容读取，其字段不是当前完整同步合同。创建与编码须在同一服务器线程，源 Map 与条目在此期间不可变；浅拷贝不保证并发安全。

## 光影规则更新

服务器按连接保留最近报告，关闭白名单时也不丢弃。规则开启或收紧后向支持的客户端发送带规则版本的重报请求，客户端包名没有变化也重报，服务器忽略先前版本的迟到报告；15秒未回复则断开并提示重新加入。普通报告保持旧包体，版本扩展只回应支持它的新服务器。

旧客户端没有重报能力时，以已有报告重评；没有报告的连接有15秒报告窗口，可重新加入报告。此兼容分支不能保证报告与刚发生的光影切换同步。规则用于正常客户端检测与执行，不提供对篡改客户端自报数据的防作弊保证。
