# S8 API 兼容边界与已确认方案

现有api.role.v2是SRE集成API。RoleCombatHooks涉及PlayerBodyEntity，RoleShopHooks涉及ShopEntry，RoleQuery涉及上游GameMode，状态/组件入口涉及CCA。把它们直接删除、换参数/返回值会破坏已编译附属模组。本轮保留全部旧公开声明，未承诺脱离SRE独立加载。

Mike 已回复“没问题”，确认：保留现有 SRE 类型接口；独立于上游类型的接口如需开发，另加新版本，旧签名继续支持。当前 S8 不进行破坏性 API 重设计。ROLE-API-23 按已确认的兼容边界结项。

GameModeConfigScope是公开的gameModes自定义JSON存储容器。没有生产消费者不等于允许直接移除下游入口。本轮明确其不自动控制内置玩法，防止把enabled误当有效模式开关；读取缺失作用域不自动保存，getOrCreate/set后仍需正常配置保存。嵌套JSON读取返回快照，变更须显式setSetting；这些快照不能用来绕过dirty/提交过程。

Mike 已回复“没问题”，确认：GameModeConfigScope 保留为明确的配置存储 API；影响内置玩法的行为另行定义，包括具体字段、生效时机、热更新及兼容规则。本轮不接通未定义的玩法语义。X-CUT-12 按此契约结项。

已有入口保留：RoleActionSpec.of、RoleForceApi.queueRoleType(int)、RoleActionResult.reject(String)、RolePatch.ColorPatch及RoleChangeApi.DefaultHolder。新增入口均为增量：builder、RoleAssignmentType、RoleActionReason、fixedColor。typed原因不占用自定义字符串空间，不改变现有网络key；rejectReason单独命名避免对旧reject(null)制造重载歧义。
