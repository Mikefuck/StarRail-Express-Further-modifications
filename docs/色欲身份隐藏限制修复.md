# 色欲身份隐藏限制的生命周期（2.0.27）

适用：Minecraft 1.21.1 / Fabric，仓库固定的 SRE 4.3.0 依赖。
服务端和客户端都应安装本版本核心；客户端需要识别新增的同步字段。

## 状态与来源

- 色欲造成的隐藏单独记账，不再通过 `refreshViews()` 每 5 刻写入 `penaltyExpiry = -1`。
- 在上游 `DeathPenaltyComponent.hasPenalty()` 合并色欲来源，沿用现有身份名称、高亮等显示入口。
- 阴谋家的施加和自动清理逻辑继续由上游处理。色欲的施加、维持和解除均不修改上游惩罚计时、相机 UUID、位置锁定或状态效果。
- 每个服务端 tick 结束时观察有效色欲、淘汰及在线状态，只有最终隐藏标志发生变化才同步，不重复施加惩罚。
- 有效色欲必须属于当前活动对局、仍在线且确实存活。死亡后保留职业信息、休息区的冒险模式和断线实体都不能维持隐藏。
- 最后一名有效色欲消失后撤销色欲来源；若仍有阴谋家、医生计时、相机或位置惩罚，身份仍按上游规则隐藏。

## 管理员指令

保留 `/tmm:game penalty stop` 的既有命令树、权限与验证要求，以及只能由玩家执行的要求。
其成功分支现在仅登记“本次死亡的色欲豁免”，不再清空整个死亡惩罚组件。
反馈会说明是否仍有其他来源的惩罚。

豁免按对局和 UUID 绑定当前死亡周期，保留到受限玩家真正复活或该局结束：

- 重连、换维度、休息区往返、重新判罚，以及色欲复活或切换职业，不重置本次死亡的豁免。
- 真正复活后再次死亡，重新适用色欲限制。
- 新一局不继承上局死亡和豁免；离线玩家同样清除。
- 普通 `init()` / `clear()`、自动惩罚到期不会登记管理员豁免。
- 对存活玩家执行指令，不会提前豁免下一次死亡。

## 同步与诊断

在原死亡惩罚组件的同步 NBT 中增加 `habitrain_core:lust_identity_hidden`。
客户端读到 `false` 或缺失字段时会替换此前的隐藏状态。
上游清理检查仅处理原有惩罚字段，避免把色欲的独立标志当成已过期的计时惩罚。

服务端在色欲隐藏状态变化和管理员豁免时输出 `[LustRestriction]` 日志，包含玩家、所属对局、有效色欲数量及上游惩罚/相机/位置字段。
排查时应同时核对实际安装的核心和 SRE 版本、服务端最终标志、客户端收到的同步值。
服务端已清除色欲来源而仍有其他惩罚，不属于色欲解除失败。

## 验证范围

自动测试覆盖死亡周期、持续豁免、重判/UUID 重连、复活后再次死亡、新局隔离、客户端清除同步、不重复同步，以及实际 SRE 字节码中的 Mixin 目标。
另用隔离的开发客户端检查真实 Mixin 应用和身份隐藏同步入口。

多人实际对局仍应复验：单/多名色欲死亡、色欲复活/离线/职业切换、管理员解除、阴谋家和相机/位置惩罚叠加，以及休息区、重连和下一局。

构建使用项目 wrapper：`./gradlew build --no-daemon`（Windows：`.\gradlew.bat build --no-daemon`）。
交付前确认本次构建的 Java 子进程退出，将成品 JAR 复制到 `D:\Backup\mc mod\临时`。
