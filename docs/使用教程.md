## 第一部分：环境准备与依赖接入

### 1.1 玩家与服主安装

- **服务端**：安装 Fabric Loader `0.18.2+`，将 `fabric-api-0.116.13+1.21.1.jar`、`starrailexpress-4.3.0.jar`、`player-animator-fabric-2.0.4+1.21.1.jar` 以及本模组 `habitrain_core-2.0.2-restored.jar` 和可选前置模组（`voicechat`、`betel-nut-mod`）放入 `mods/` 文件夹中。
- **客户端**：双端必须同时安装相同版本的 `habitrain_core` 与 `playeranimator`，客户端可安装 ModMenu，在游戏内通过图形化界面直接管理各项功能。

### 1.2 开发者 Gradle 依赖引入

在开发下游扩展模组时，推荐将 SRE 与 HabiTrain Core 的 JAR 放入附属模组的 `libs/` 目录中：

```groovy
repositories {
    mavenCentral()
    maven { url "https://maven.kosmx.dev/" } // playerAnimator 仓库
    flatDir {
        dirs "libs"
    }
}

dependencies {
    minecraft "com.mojang:minecraft:1.21.1"
    mappings loom.officialMojangMappings()
    modImplementation "net.fabricmc:fabric-loader:0.18.2"
    modImplementation "net.fabricmc.fabric-api:fabric-api:0.116.13+1.21.1"

    // 核心前置模组
    modImplementation files("libs/star_rail_express-4.3.0-dev.jar")
    modImplementation files("libs/habitrain_core-2.0.2.jar")
    modImplementation "dev.kosmx.player-anim:player-animation-lib-fabric:2.0.4+1.21.1"
    
    // 可选依赖
    modCompileOnly files("libs/voicechat-fabric-1.21.1-2.5.28.jar")
}
```

### 1.3 fabric.mod.json 声明与 Entrypoints

在附属模组 `src/main/resources/fabric.mod.json` 中声明 HabiTrain Core 专属扩展入口：

```json
{
  "schemaVersion": 1,
  "id": "my_sre_addon",
  "version": "1.0.0",
  "name": "My SRE Addon",
  "environment": "*",
  "entrypoints": {
    "main": [
      "com.example.addon.MyAddonMod"
    ],
    "client": [
      "com.example.addon.client.MyAddonClient"
    ],
    "habitrain:role_extensions": [
      "com.example.addon.role.AddonRoleExtensionProvider"
    ],
    "habitrain:role_client_extensions": [
      "com.example.addon.client.role.AddonRoleClientProvider"
    ]
  },
  "depends": {
    "fabricloader": ">=0.18.2",
    "minecraft": "~1.21.1",
    "habitrain_core": ">=2.0.2",
    "starrailexpress": "*",
    "playeranimator": ">=2.0.4"
  }
}
```

## 第二部分：服主与玩家游戏机制指南

### 2.1 停电模式（Blackout Mode）玩法指南

停电模式是 HabiTrain Core 自带的一套完整的独立恐怖求生与社交推理模式：

```text
┌─────────────────────────────────────────────────────────────┐
│                       停电模式核心循环                      │
├─────────────────────────────────────────────────────────────┤
│   [电力充沛阶段] ───(电力耗尽/破坏)───► [全场断电/盲目黑暗]   │
│         ▲                                    │              │
│         │                                    ▼              │
│   [恢复供电/添煤] ◄───(紧急会议/拉响号角)─── [黑市求生/刺杀]  │
└─────────────────────────────────────────────────────────────┘
```

1. **电力与发电机维护**：
   - 游戏开始后，发电机持续消耗燃煤维持全车供电。
   - 好人阵营需要时刻关注发电机状态，拾取燃煤为发电机添煤（`add_coal`）以延长供电时间。
   - 杀手阵营可寻找机会破坏电线（`sabotage_wiring`）或破坏发电机（`furnace_explosion`），制造突发停电。
2. **黑暗与致盲危机**：
   - 一旦电力耗尽进入停电阶段，所有非杀手玩家将陷入强烈的盲目与黑暗效果，伴随心跳声与警报音效。
   - 玩家可携带手电筒照明，或在黑市终端购买照明与防卫物资。
3. **日常任务与坏人假任务系统**：
   - 内置 7 种日常停电任务：`饱腹`（进食特定食物）、`饮水`（饮用药水/水瓶）、`搜寻背包`（搜寻箱子背包）、`嚼槟榔`（需咀嚼槟榔并应对成瘾）、`撸猫`（抚摸列车猫咪）、`独处`（离开人群独自停留指定时长）、`对视`（与其他玩家正面保持对视）。
   - 好人完成任务推进团队胜度；坏人会自动获得一模一样的假任务清单，用于混入人群伪装行动。
4. **黑市枪械商店与电话系统**：
   - 玩家完成任务积累货币后，可在特定黑市贩卖机购买「沙漠之鹰」与「专属弹药」进行自卫防身。
   - 遭遇险情时可前往车厢固定点位使用电话亭拨打救援电话，或在关键时刻拉响号角召集全员召开紧急会议投票。

### 2.2 维修人员模式（Repair Mode）修图与隔离

在多人服务器运营中，常有地图需要排查方块缺失、线路故障或装饰修缮。

1. **进入维修模式**：
   - 管理员执行 `/habi_api repair <地图ID>`（支持 Tab 实时自动补全当前可用地图）。
   - 玩家将立即切换至创造模式并传送至该地图，且该地图被**自动上锁**。
2. **智能隔离保护**：
   - **凡处于维修锁定状态的地图，会自动从所有玩家的模式/地图投票池和随机选图池中剔除**，彻底防止正在维修的半成品地图被普通对局选入。
3. **退出与恢复**：
   - 维修完成后，执行 `/habi_api repair cancel` 即可退出维修状态，系统会自动恢复玩家原本的生存模式与对局参与状态。
   - 管理员可执行 `/habi_api repair list` 查看当前所有维修人员与被锁地图，或执行 `/habi_api repair unlock <地图ID>` 强制解锁地图。

### 2.3 淘汰玩家休息区（Eliminated Rest Area）

- **痛点解决**：传统 SRE 模式中玩家死亡后只能幽灵自由漫游，经常产生卡顿、剧透或无聊挂机。
- **机制运作**：玩家在对局中死亡/被淘汰后，屏幕中央将出现休息区交互提示；按下专属快捷键即可一键传送至安全的「淘汰玩家专属休息区」与其他淘汰玩家互动交流，亦可随时再次按键切换回全图自由观战。

#### 2. 细粒度动画规则配置
- **随机选择与去重**：当多位获胜玩家登台时，系统会自动互斥去重，分配互不相同的庆祝动作。
- **单人优先动作适配**：如「从容静坐」、「悬浮冥想」在单人 MVP 时优先触发，团队获胜时自动回退为站立姿势。
- **角色道具手持展示**：开启后，获胜玩家在结算时将手持其职业代表性道具。
- **播放速率调节**：可在 0.5x ~ 1.5x 之间调整动画播放快慢。
- **逐项开关控制**：服主可在 ModMenu 中逐一启用或禁用任意动作。
- 资产授权详情见 [THIRD_PARTY_LICENSES/MVP_ANIMATIONS.md](../THIRD_PARTY_LICENSES/MVP_ANIMATIONS.md)。

### 2.5 七宗罪与七美德体系机制

#### 👿 七宗罪角色（Seven Sins）
七大具备极强博弈深度的中立/独立阵营角色，各具独特的胜利条件与互斥规则：
- **傲慢（Pride）**：自视甚高，拥有特殊的击杀判定与傲视群雄的胜负结算。
- **嫉妒（Envy）**：窥探他人生存，具有复制或反制他人能力的机制。
- **暴怒（Wrath）**：受到攻击或目击冲突时获得狂暴状态与爆发移速。
- **懒惰（Sloth）**：极度消极，与 Simple Voice Chat 联动，具备独特的静音与迟缓防御机制。
- **贪婪（Greed）**：
  - 拥有专属道具「贪婪钱袋（Greed Pouch）」，可向其他玩家发起匿名交易。
  - 双方支持安全的双确认流程（GUI 点击确认或输入 `/habi_api greed_trade confirm` / `cancel`）。
- **暴食（Gluttony）**：通过大量进食获取增益，暴食状态下免疫部分负面效果。
- **色欲（Lust）**：绑定同伴心印，形成同生共死的羁绊关系。

#### 🕊️ 七美德词条修饰符（Seven Virtues）
七美德作为词条修饰符附加在玩家身上，严格遵循**单美德独占互斥规则**（玩家获得任一美德时会自动清除其他美德）：
- **纯洁（Chastity）**：抵御一次致命伤害或负面效果。
- **谦逊（Humility）**：完成任务时为全队额外贡献进度加成。
- **宽容（Mercy）**：仅好人阵营可获得，受到攻击时使攻击者短暂迟滞。
- **节制（Temperance）**：控制欲望，商店购买物品时获得折扣或返利。
- **勤勉（Diligence）**：大幅加快各类任务的交互与推进速度（与耐心硬互斥）。
- **耐心（Patience）**：原地等待蓄力，随时间推移积累全图视野或加速能量。
- **慷慨（Generosity）**：深度兼容上游 `noellesroles` 的慷慨修饰符，可为他人转移物资。

### 2.7 ModMenu 可视化配置中心运维实战（四大分类）

按下 `Esc -> 选项 -> 模组 -> HabiTrain Core -> 配置` 打开全中文配置中心。界面由**左侧永久一级导航栏**与**右侧二级子标签页及内容区**组成：

#### 分类 1：游戏内（In-Game，对局体验）
1. **小游戏配置（InGameMinigamesPage）**：
   - 查看所有已注册任务（原版与 DLC 扩展任务）。
   - 按地图单独勾选启用或禁用特定任务，微调任务生成策略。
2. **数值平衡配置（InGameBalancePage）**：
   - **警长人数分母 (`sheriffCountDivisor`)**：默认 4，即每 4 名玩家生成 1 名警长。
   - **小刀耐久总开关 (`knifeDurabilityEnabled`)**：开启后杀手小刀具有耐久消耗与充能 CD 机制。
   - **停电致盲效果开关**：控制停电时是否给玩家施加致盲黑暗效果。
   - **临时电力价格 (`tempPowerPrice`)**：调整黑市中购买发电机备用电力的价格。
3. **环境配置（InGameEnvPage）**：
   - 设定对局中（Match）与结算后（Post-Match）的天气（晴天/降雨/雷暴）与时间锁定。
   - 配置动态天气变化与环境雾效。

#### 分类 2：游戏外（Out-Game，大厅与投票）
1. **投票配置（OutGameVotePage）**：
   - 模式投票倒计时与地图投票倒计时秒数调节（默认各 30 秒）。
   - 启用「按在线人数动态抽图」（`playerCount.enabled`）及单次抽图数量（`drawCount`）。
   - 投票预设维护与地图介绍图（Map Intro）本地缓存管理。
2. **大厅环境配置（OutGameLobbyEnvPage）**：
   - 锁定大厅等待阶段的时间（如永远正午）与天气（晴朗）。
   - 开启大厅自动语音群组（`lobbyVoiceGroupEnabled`）。
3. **光影白名单配置（OutGameShaderPage）**：
   - 开启/关闭 Iris 光影检测防护总开关。
   - 维护允许客户端使用的光影包文件名列表（如 `ComplementaryReimagined_r5.1.1.zip`）。
4. **MVP 动画配置（OutGameMvpAnimationsPage）**：
   - MVP 动画总开关、随机抽取、避免重复、手持角色物品展示。
   - 动画播放速度滑块（0.5x ~ 1.5x）。
   - 30 种动作姿势的逐项独立启用/禁用复选框。

#### 分类 3：游戏模式（Game Modes，任务与角色）
1. **任务配置（ModeTasksPage）**：
   - 按游戏模式划分任务池，配置 DLC 任务相对于原版任务的额外生成权重加成（`dlcProbabilityTarget`）。
2. **角色覆盖配置（ModeRolesPage）**：
   - 查看 v1 角色覆盖（MODIFY / REPLACE）条目状态、启用状态与生效参数。
3. **角色扩展配置（RoleExtensionsPage）**：
   - 查看 v2 Provider 与 Entry 列表、加载状态与依赖清单。
   - 热启用/禁用 Provider 或 Entry，手动设置字段补丁冲突的获胜条目。

#### 分类 4：其他（Other，扩展设置）
- 兼容性选项、网络同步机制、只读/OP4 权限门控分级与调试日志输出。

> **快照机制提示**：在大厅阶段修改配置会即时生效；若在对局进行中修改，系统会自动存入待定快照（Pending Snapshot），待本局结束重置时平滑编译生效，确保正在进行的对局零抖动。

### 2.8 安全防护系统配置（光影检测、门控与转职安全）

#### 1. Iris 光影白名单检测系统
- **背景**：部分光影包具备夜视或高亮轮廓透视，破坏停电与黑夜对抗。
- **机制**：客户端进入世界后自动上报当前 Iris 光影文件名；服务端与白名单列表比对，若未通过则给出警告或强制移出对局。
- **配置**：可在 ModMenu 中直接勾选添加，或在 `config/habitrain_core.json` 中配置：
  ```json
  "shaderWhitelistEnabled": true,
  "shaderWhitelist": [
    "ComplementaryReimagined_r5.1.1.zip",
    "BSL_v8.2.09.zip"
  ]
  ```

#### 2. ModMenu 管理员门控（Menu Gate）
- **背景**：防止普通玩家越权打开 ModMenu 配置界面窥探或修改服务端对局参数。
- **控制台命令（必须由控制台 OP 4 执行）**：
  ```text
  /habi_api menugate enable                # 开启门控
  /habi_api menugate add <玩家名>          # 授权某玩家访问
  /habi_api menugate remove <玩家名>       # 撤销访问权限
  /habi_api menugate list                  # 查看授权名单
  ```

#### 3. 角色安全转职策略（ForcedRandomRoleChangePolicy）
- 角色在受到强制转职（如技能重置、随机转职）时，必须通过 `RoleChangeApi` 的事务化管道。
- 平台会自动清理原角色的 CCA 组件、持久状态数据、药水增益与计分板，并执行安全白名单校验，杜绝非法跨职业转职引发的逻辑崩坏。

### 2.9 语音群组、大厅自动组队与地图投票预设

- **语音群组**：配合 `Simple Voice Chat`，管理员可执行 `/instantgroup [范围]` 快速将周围玩家拉入临时语音会议。
- **大厅自动组队**：等待大厅阶段所有玩家自动处于同一语音频段；对局开始时无缝解散，回归 3D 空间距离衰减语音。
- **地图投票预设与介绍图缓存**：支持服务器下发地图预设与标签信息，客户端本地自动缓存地图封面与简介，大幅降低投票界面的网络负载与卡顿。

## 第三部分：核心 API 开发实战

### 3.1 任务系统 API（TaskRegistry）

HabiTrain Core 提供了高度可定制、支持直觉透视高亮与生命周期监控的任务框架。所有任务在模组初始化期通过 `TaskRegistry.register` 进行注册：

```java
package com.example.addon;

import com.habitrain.core.api.TaskCategory;
import com.habitrain.core.api.TaskRegistry;
import net.fabricmc.api.ModInitializer;
import net.minecraft.network.chat.Component;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.item.Items;

public final class MyAddonTasks implements ModInitializer {
    @Override
    public void onInitialize() {
        TaskRegistry.register("my_addon", "clean_window", builder -> builder
                // 任务显示名称
                .displayName("清理车窗积雪")
                // 任务分类（MURDER, REPAIR, ALL, CUSTOM）
                .category(TaskCategory.ALL)
                // 适用游戏模式（默认 "sre:base" 适用于所有标准 SRE 模式）
                .gameMode("sre:base")
                // 任务在随机池中的权重
                .weight(1.0F)
                // 任务限时（秒），超时自动判负
                .timeLimit(90)
                // 直觉透视颜色 (ARGB 整数格式)
                .instinctColor(100, 200, 255, 220)
                // 关联方块类型 ID（用于透视扫描定位）
                .blockTypeId(42)
                // 任务分配给玩家时的回调
                .onAssign((player, task) -> {
                    task.setMaxProgress(5); // 设置总步骤为 5
                    player.sendSystemMessage(Component.literal("§e你接到了新任务：清理车窗积雪！"));
                })
                // 每 tick 检查是否完成
                .completionChecker((player, task) -> task.getProgress() >= task.getMaxProgress())
                // 任务成功完成回调
                .onComplete((player, task) -> {
                    player.sendSystemMessage(Component.literal("§a车窗清理完毕，视野恢复清晰！"));
                })
                // 任务超时或失败回调
                .onFail((player, task) -> {
                    player.sendSystemMessage(Component.literal("§c清理超时，任务失败！"));
                })
                // 任务被移除时的资源清理
                .onRemove((player, task) -> {
                    // 清理计分板或自定义粒子效果
                }));
    }
}
```

#### 任务生命周期执行顺序
```text
分配给玩家 (onAssign)
       │
       ▼
[ 每 Tick 循环 ] ───► 限时检查 (timeLimit) ──(超时)──► onFail
       │
       ├────────────► onTick(player, task)
       │
       ├────────────► completionChecker(player, task) ──(达到目标)──► onComplete
       ▼
任务结束/重置 ───────► onRemove / onReclaim
```

### 3.2 任务道具安全回收机制（ItemReclaimHelper）

许多任务需要在分配时发放临时工具（如刷子、扳手），并在任务结束或取消时收回。若处理不当容易造成玩家刷物品或背包残留垃圾。`ItemReclaimHelper` 提供了标准打标与安全回收体系：

```java
TaskRegistry.register("my_addon", "repair_pipe", builder -> builder
        .displayName("维修管道")
        .category(TaskCategory.ALL)
        .onAssign((player, task) -> {
            // 创建临时道具并打上防刷标签
            ItemStack wrench = new ItemStack(Items.TRIPWIRE_HOOK);
            wrench.setHoverName(Component.literal("§b专用管道扳手 (临时)"));
            ItemReclaimHelper.tagGrantedItem(wrench, "my_addon:repair_pipe");
            player.getInventory().add(wrench);
        })
        .onReclaim((player, task) -> {
            // 当任务被取消、玩家掉线或对局重置时，精准回收带有该标签的物品
            ItemReclaimHelper.reclaim(player, "my_addon:repair_pipe");
        })
        .onComplete((player, task) -> {
            // 正常完成时同样收回临时道具
            ItemReclaimHelper.reclaim(player, "my_addon:repair_pipe");
            player.sendSystemMessage(Component.literal("§a管道维修成功！"));
        }));
```

### 3.3 自定义游戏模式开发（GameModeRegistry）

要向 SRE 引入一套全新的玩法规则，只需实现 `GameMode` 接口并注册到 `GameModeRegistry`：

```java
package com.example.addon.mode;

import com.habitrain.core.api.GameMode;
import com.habitrain.core.api.GameModeRegistry;
import com.habitrain.core.api.TaskCategory;
import com.habitrain.core.api.WinResult;
import net.minecraft.server.level.ServerLevel;
import net.minecraft.server.level.ServerPlayer;
import java.util.List;
import java.util.Optional;

public final class CustomSurvivalMode implements GameMode {
    public static final String LOGICAL_ID = "my_addon:survival";
    private boolean active = false;

    @Override
    public String getId() {
        return LOGICAL_ID;
    }

    @Override
    public String getDisplayName() {
        return "极寒生存模式";
    }

    @Override
    public List<TaskCategory> getTaskCategories() {
        return List.of(TaskCategory.ALL);
    }

    @Override
    public boolean isActive(ServerLevel level) {
        return active;
    }

    @Override
    public void onStart(ServerLevel level) {
        active = true;
        // 初始化本局数据、发放初始装备、重置天气
    }

    @Override
    public void onTick(ServerLevel level) {
        // 每 tick 驱动模式规则（如全图暴风雪降温扣血等）
    }

    @Override
    public Optional<WinResult> checkWinCondition(ServerLevel level) {
        // 胜负判定逻辑
        List<ServerPlayer> alive = level.players().stream()
                .filter(p -> !p.isSpectator())
                .toList();
        if (alive.size() <= 1) {
            return Optional.of(WinResult.singleWinner(
                    alive.isEmpty() ? null : alive.get(0).getUUID(),
                    "极寒之王诞生！"));
        }
        return Optional.empty();
    }

    @Override
    public void onCleanup(ServerLevel level) {
        active = false;
        // 无论正常结束还是意外崩溃，都应安全清理临时实体与方块
    }
}
```
在模组初始化时注册并启动：
```java
// 注册模式
GameModeRegistry.register("my_addon", "survival", new CustomSurvivalMode());

// 开启模式
GameModeRegistry.start("my_addon:survival", serverLevel);

// 结束模式
GameModeRegistry.stop(serverLevel, WinResult.noWinner("游戏结束"));
```

### 4.3 角色扩展 API v2 深度开发实战

角色扩展 API v2 是 HabiTrain Core 最强大的标准化角色平台，采用声明式 Profile 架构。

#### 4.3.1 ADD：声明并注册全新角色

创建 `RoleExtensionEntrypoint` 实现类：

```java
package com.example.addon.role;

import com.habitrain.core.api.role.v2.RoleExtensionEntrypoint;
import com.habitrain.core.api.role.v2.RoleExtensionRegistrar;
import com.habitrain.core.api.role.v2.RoleKey;
import com.habitrain.core.api.role.v2.definition.*;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.item.Items;
import java.util.List;

public final class AddonRoleExtensionProvider implements RoleExtensionEntrypoint {
    public static final RoleKey PLAGUE_DOCTOR = RoleKey.of("my_addon", "plague_doctor");

    @Override
    public void register(RoleExtensionRegistrar registrar) {
        registrar.add(RoleDefinition.builder(PLAGUE_DOCTOR)
                // 1. 外观展示配置
                .presentation(RolePresentation.builder()
                        .color(0xFF4B8B3B) // 角色主题色 (ARGB)
                        .nameKey("role.my_addon.plague_doctor")
                        .descriptionKey("role.my_addon.plague_doctor.desc")
                        .simpleDescriptionKey("role.my_addon.plague_doctor.simple")
                        .build())
                // 2. 阵营配置（neutral 中立独立阵营）
                .faction(RoleFactionProfile.builder().neutral().build())
                // 3. 生成规则（最多 1 人，需 6 人以上对局才生成）
                .spawn(RoleSpawnProfile.builder()
                        .defaultMax(1)
                        .enableChance(100)
                        .needPlayerCount(6)
                        .build())
                // 4. 兼容性配置（允许被随机池选中）
                .compatibility(RoleCompatibilityProfile.builder()
                        .canBeRandomed()
                        .build())
                // 5. 初始物品
                .inventory(RoleInventoryProfile.of(List.of(
                        new ItemStack(Items.GLASS_BOTTLE, 3),
                        new ItemStack(Items.SPLASH_POTION)
                )))
                // 6. 体力与冲刺时间（秒）
                .maxSprintTime(20)
                .build());
    }

    @Override
    public boolean requiresClient() {
        return true; // 若有配套客户端 HUD/渲染，返回 true 启用安全握手校验
    }
}
```

```java
import com.habitrain.core.api.role.v2.client.RoleClientExtensionRegistrar;

import com.habitrain.core.api.role.v2.client.RoleHudSpec;

public final class AddonRoleClientProvider implements RoleClientExtensionEntrypoint {
    @Override
    public void register(RoleClientExtensionRegistrar registrar) {
        // 注册屏幕文字 HUD 提示
        registrar.hud(RoleHudSpec.of("my_addon", "plague_hud")
                .role(AddonRoleExtensionProvider.PLAGUE_DOCTOR)
                .kind(RoleHudKind.TEXT)
                .textKey("hud.my_addon.plague_doctor.status")
                .color(0x55FF55)
                .position(6, 6)
                .build());
    }
}
```

> **注意**：所有注册操作必须且只能通过 Entrypoint 回调参数 `registrar` 执行；全局 API 中的写方法在运行时均会拒绝并抛出 `UnsupportedOperationException`。

#### 4.3.7 目录查询（RoleCatalogApi）与安全转职（RoleChangeApi）

```java
// 1. 规范化查询角色（自动解析别名与替换关系）
RoleCatalogApi.instance().find(RoleKey.of("my_addon", "plague_doctor")).ifPresent(role -> {
    String displayNameKey = role.presentation().nameKey();
});

// 2. 事务化安全转职
RoleChangeApi.instance().transform(
        player, 
        RoleKey.of("my_addon", "plague_doctor"), 
        RoleChangeCause.FORCED_RANDOM
);
```

> **安全转职策略（ForcedRandomRoleChangePolicy）**：  
> `RoleChangeApi` 会在转职前对原角色的 CCA 组件、持久状态、药水效果与计分板进行全面擦除，并保留完整的转职审计历史，杜绝非法转职导致的逻辑错乱与内存残留。请切勿直接修改底层的角色 Map。

### 5.3 角色扩展诊断命令（/habitrain roleapi）排错指南

当附属模组的角色未正常加载或出现冲突时，请按以下步骤排查：

1. **检查 Provider 加载状态**：
   ```text
   /habitrain roleapi providers
   ```
   若 Provider 显示 `FAILED` 或未出现，请检查 `fabric.mod.json` 中的 `habitrain:role_extensions` 入口类路径是否正确。
2. **检查有效角色列表与冲突**：
   ```text
   /habitrain roleapi list effective
   /habitrain roleapi list conflict
   ```
   若角色出现在 `conflict` 中，说明有两个 Mod 试图对同一个字段打互斥补丁；可使用 `/habitrain roleapi config winner <目标#字段> <获胜条目ID>` 显式指定胜者。
3. **追踪字段合并流程**：
   ```text
   /habitrain roleapi trace starrailexpress:sheriff maxSprintTime
   ```
   可清晰列出该字段从初始值经过了哪些 Provider 的 Patch 叠加，帮助快速定位数值异常。
