# 哈比列车核心使用教程

> 适用：Minecraft 1.21.1、Fabric、Java 21、HabiTrain Core 2.0.2、StarRailExpress 4.3.0
> 模组 ID：`habitrain_core`

本文面向编写附属模组的开发者，覆盖依赖接入、任务、游戏模式、投票和角色扩展的正确入口。所有公开 API 位于 `com.habitrain.core.api`；内部实现包不承诺兼容。

## 1. 接入依赖

当前项目没有发布 Maven 制品时，把 HabiTrain Core 和 SRE 开发 JAR 放入附属模组的 `libs/`：

```groovy
repositories {
    flatDir { dirs "libs" }
}

dependencies {
    modImplementation files("libs/habitrain_core-2.0.2.jar")
    modImplementation files("libs/star_rail_express-4.3.0-dev.jar")
}
```

`fabric.mod.json` 至少声明：

```json
{
  "schemaVersion": 1,
  "id": "example_mod",
  "environment": "*",
  "depends": {
    "fabricloader": ">=0.18.2",
    "minecraft": "~1.21.1",
    "java": ">=21",
    "fabric-api": "*",
    "habitrain_core": ">=2.0.2",
    "starrailexpress": "*"
  }
}
```

服务端与客户端必须使用兼容版本。包含角色展示、客户端动作或资源的 provider 应安装在双方。

## 2. 注册自定义任务

任务在附属模组 `ModInitializer.onInitialize()` 中注册：

```java
public final class ExampleMod implements ModInitializer {
    @Override
    public void onInitialize() {
        TaskRegistry.register("example_mod", "repair_radio", builder -> builder
                .displayName("维修电台")
                .category(TaskCategory.ALL)
                .gameMode("sre:base")
                .weight(1.0F)
                .timeLimit(90)
                .instinctColor(80, 180, 255, 190)
                .onAssign((player, task) -> task.setMaxProgress(3))
                .completionChecker((player, task) ->
                        task.getProgress() >= task.getMaxProgress())
                .onComplete((player, task) ->
                        player.sendSystemMessage(Component.literal("电台已修复")))
                .onFail((player, task) ->
                        player.sendSystemMessage(Component.literal("维修失败"))));
    }
}
```

任务 full ID 为 `example_mod:repair_radio`。注册表冻结后不能再注册，重复 ID 会抛异常。

### 2.1 任务回调顺序

每个未结束实例的 tick 顺序为：

```text
限时检查 → onTick → completionChecker → onComplete / onFail
```

- `TaskInstance.setProgress(...)` 会触发 `onProgressUpdate`。
- `setMaxProgress(...)` 最小值为 1。
- `markFailed()` 同时设置 failed 与 fulfilled。
- `onRemove` 用于清理状态；`onReclaim` 专门用于取消/隐藏路径回收临时道具。

### 2.2 发放可回收物品

```java
TaskRegistry.register("example_mod", "find_tool", builder -> builder
        .displayName("寻找工具")
        .category(TaskCategory.ALL)
        .onAssign((player, task) -> {
            ItemStack stack = new ItemStack(Items.IRON_PICKAXE);
            ItemReclaimHelper.tagGrantedItem(stack, "example_mod:find_tool");
            player.getInventory().add(stack);
        })
        .onReclaim((player, task) ->
                ItemReclaimHelper.reclaim(player, "example_mod:find_tool")));
```

成功完成默认不回收；取消、隐藏、强制替换等路径应走 reclaim。

## 3. 注册自定义游戏模式

实现 `GameMode`，然后用 `GameModeRegistry` 注册：

```java
public final class ArenaMode implements GameMode {
    public static final String LOGICAL_ID = "example_mod:arena";
    public static final TaskCategory ARENA_TASK =
            new TaskCategory("example_mod:arena_task", "竞技任务", LOGICAL_ID);

    @Override public String getId() { return LOGICAL_ID; }
    @Override public String getDisplayName() { return "竞技场"; }
    @Override public List<TaskCategory> getTaskCategories() { return List.of(ARENA_TASK); }
    @Override public boolean isActive(ServerLevel level) { return false; }

    @Override public void onStart(ServerLevel level) {
        // 初始化本局
    }

    @Override public Optional<WinResult> checkWinCondition(ServerLevel level) {
        return Optional.empty();
    }

    @Override public void onCleanup(ServerLevel level) {
        // 无论正常停止还是启动失败，都应安全清理
    }
}

GameModeRegistry.register("example_mod", "arena", new ArenaMode());
```

注册键是 `example_mod:arena`，不一定等于 `GameMode.getId()`。`start/get` 使用注册键；任务的 `gameMode(...)` 使用逻辑 ID。

```java
GameModeRegistry.start("example_mod:arena", level);
GameModeRegistry.stop(level, WinResult.noWinner("对局结束"));
```

每个世界同时只能有一个主动模式。`tickAll` 只驱动由 `start(...)` 放入 active 表的模式。

## 4. 使用投票 API

### 4.1 通用选项投票

```java
List<VoteOption> options = List.of(
        new VoteOption("day", "白天"),
        new VoteOption("night", "夜晚")
);

OptionVoteApi.start(level, "example_mod:time_vote", options, 30, result -> {
    String winner = result.winnerId();
    boolean random = result.randomPick();
});
```

候选项是字符串 ID，不是玩家 UUID。`OptionVoteApi.cast(level, player, null)` 表示弃票。

### 4.2 模式→地图投票

```java
ModeMapVoteConfig config = new ModeMapVoteConfig();
config.modeDurationSeconds = 45;
config.mapDurationSeconds = 45;

ModeMapVoteApi.start(level, config);
ModeMapVoteApi.getSnapshot(level).ifPresent(snapshot -> {
    String phase = snapshot.phase();
    String selectedMode = snapshot.selectedModeId();
});
```

## 5. 选择角色 API 版本

| 需求 | 推荐入口 |
|---|---|
| 只稳定替换一个角色，或对现有角色做兼容修改 | v1 `RoleOverrideApi` |
| 新增角色、声明式合并多个补丁、alias 迁移 | v2 `RoleExtensionRegistrar` |
| 受管事件 hooks、状态、网络动作、语音/聊天策略 | v2 |
| 有效角色目录、事务化转职、快照与诊断 | v2 |

v1 不弃用；v2 当前是 preview / experimental。不要在同一需求里同时用 v1 与 v2 争夺同一个角色字段或身份。

## 6. v1 角色替换/修改入门

v1 注册发生在普通 `ModInitializer.onInitialize()`：

```java
private static final ResourceLocation TARGET =
        ResourceLocation.parse("starrailexpress:civilian");

RoleOverrideApi.registerModify(ModifyRoleDefinition.builder()
        .sourceModId("example_mod")
        .entryKey("armed_civilian")
        .displayName(Component.literal("武装平民"))
        .description(Component.literal("增加初始武器和技能"))
        .targetRoleId(TARGET)
        .defaultItemsPatch((original, server) ->
                List.of(new ItemStack(Items.IRON_SWORD)))
        .managedSkillPatch(original -> List.of(
                RoleSkill.skill(
                        ResourceLocation.fromNamespaceAndPath("example_mod", "boost"),
                        "skill.example_mod.boost",
                        context -> true)
                        .cooldownSeconds(30)
                        .showOnHud(true)
                        .build()))
        .build());
```

v1 MODIFY 保留原角色 ID 和对象。REPLACE 需要 provider 自己构造新的 `SRERole`，但不要预先调用 `TMMRoles.registerRole()`；Core 在条目激活时注册并过滤目标。

详细规则见角色扩展 v2 教程中的 v1 迁移章节，或工作区 skill `using-habitrain-role-override`。

## 7. v2 角色扩展入门

在 `fabric.mod.json` 添加：

```json
{
  "entrypoints": {
    "habitrain:role_extensions": [
      "com.example.roles.ExampleRoleProvider"
    ],
    "habitrain:role_client_extensions": [
      "com.example.roles.client.ExampleRoleClientProvider"
    ]
  }
}
```

通用 provider：

```java
public final class ExampleRoleProvider implements RoleExtensionEntrypoint {
    public static final RoleKey DOCTOR = RoleKey.of("example_mod", "doctor");

    @Override
    public void register(RoleExtensionRegistrar registrar) {
        registrar.add(RoleDefinition.builder(DOCTOR)
                .presentation(RolePresentation.builder()
                        .color(0xFF60A060)
                        .nameKey("role.example_mod.doctor")
                        .descriptionKey("role.example_mod.doctor.description")
                        .build())
                .faction(RoleFactionProfile.builder().innocent().build())
                .spawn(RoleSpawnProfile.builder().defaultMax(1).needPlayerCount(6).build())
                .compatibility(RoleCompatibilityProfile.builder().canBeRandomed().build())
                .maxSprintTime(20)
                .build());
    }

    @Override
    public boolean requiresClient() {
        return true;
    }
}
```

`requiresClient()` 只在 provider 必须依赖客户端扩展/资源时返回 `true`。返回 true 后，缺少或加载失败的客户端 provider 会使受管动作握手 fail-closed。

客户端 provider 必须放在只由物理客户端加载的类中：

```java
public final class ExampleRoleClientProvider implements RoleClientExtensionEntrypoint {
    @Override
    public void register(RoleClientExtensionRegistrar registrar) {
        registrar.hud(RoleHudSpec.of("example_mod", "doctor_hint")
                .role(ExampleRoleProvider.DOCTOR)
                .kind(RoleHudKind.TEXT)
                .textKey("hud.example_mod.doctor")
                .color(0xFFFFFF)
                .position(4, 4)
                .build());
    }
}
```

注册只能使用 entrypoint 回调参数。下列写法是错误的：

```java
// 错误：只读兼容门面，调用会抛 UnsupportedOperationException
RoleExtensionApi.instance().registrar().add(definition);

// 错误：客户端全局 API 也不能直接注册
RoleClientExtensionApi.instance().hud(spec);
```

完整 ADD/MODIFY/REPLACE/ALIAS、hooks、state、action、client、voice/chat 和 diagnostics 用法见 [角色扩展 API v2 使用教程](角色扩展API-v2使用教程.md)。

## 8. 配置与调试

| 文件 | 用途 |
|---|---|
| `config/habitrain_core.json` | 任务、模式、投票、环境等主配置 |
| `config/habitrain_role_v2.json` | v2 provider、条目、冲突赢家和全局 hook 配置 |

常用角色诊断命令：

```text
/habitrain roleapi providers
/habitrain roleapi list effective
/habitrain roleapi inspect <role>
/habitrain roleapi trace <role> <field>
/habitrain roleapi snapshot
/habitrain roleapi actions
/habitrain roleapi capabilities
/habitrain roleapi manifest
```

只读诊断需要 OP 2；写配置需要 OP 4。大厅内配置修改立即生效；对局中修改进入 pending snapshot，下一局生效。

## 9. 发布检查

1. 使用 Java 21 执行 `./gradlew build`。
2. 检查 `build/release/habitrain_core-2.0.2-restored.jar`。
3. 对角色、动作或状态改动执行客户端 + 专用服务器双端测试。
4. 检查 provider 在 `/habitrain roleapi providers` 与 `list effective` 中状态正确。
5. 开关 provider/entry，确认大厅立即更新、局中只生成 pending。
6. 按工作区约定把最终 JAR 复制到 `../临时/`。

更多接口签名见 [API 参考手册](API参考手册.md)。
