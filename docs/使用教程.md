## 1. 概述

本模组**完全接管** StarRailExpress（哈比列车）的原版任务系统，通过 Mixin 覆盖任务生成逻辑，将原版任务和 DLC 自定义任务统一管理。

### 核心能力

| 能力 | 说明 |
|------|------|
| 🔧 **统一注册 API** | DLC 模组几行代码即可注册自定义任务，无需修改 SRE 本体 |
| 🎨 **ModMenu 配置 GUI** | 可视化管理所有任务的开关、颜色、奖励、地图过滤 |
| ⚖️ **自动平衡系统** | DLC 任务出现概率自动稳定在目标比例，加新模组无需调配置 |
| 🔍 **方块透视渲染** | 自定义方块高亮边框，颜色和描边粗细可配置 |
| 💰 **奖励系统** | 每个任务可独立配置金币/情绪奖励 |
| 🗺️ **多模式支持** | 谋杀模式 (TMM)、修机模式 (Repair)、通用任务、自定义任务 |

### 架构一览

```
StarRailExpress 原版任务系统 (Task枚举: SLEEP / EAT / ...)
        │
        ▼ Mixin 接管 (GenerateTaskMixin)
哈比列车任务API
  ├─ 原版任务（代理为内置任务，受配置控制）
  ├─ DLC 自定义任务（来自其他模组）
  └─ 统一权重池 → 加权随机选择
```

## 2. 安装与验证

### 前置要求

| 模组 | 版本 | 说明 |
|------|------|------|
| StarRailExpress | ≥4.2.0 | 必须 |
| Fabric API | ≥0.116.12 | 必须 |
| ModMenu | ≥11.0.3 | **可选**，提供配置界面入口 |

### 安装步骤

1. 将 `habitrain_taskapi-1.0.0.jar` 放入 `mods/` 目录
2. 确保 StarRailExpress 和（推荐）ModMenu 已安装
3. 启动游戏
4. 主菜单左下角版本号会显示 `| Mike任务api加载中` 表示加载成功

### 验证

服务端控制台应输出：
```
[habitrain_taskapi/INFO]: 哈比列车任务API 初始化完成！
[habitrain_taskapi/INFO]: 已注册 15 个内置任务
```

### 客户端 vs 服务端

| 端 | 必须安装？ | 作用 |
|----|-----------|------|
| **服务端** | ✅ 必须 | 任务生成、配置存储、回调执行 |
| **客户端** | ✅ 必须 | ModMenu 配置界面、透视渲染 |

## 3. 玩家指南：ModMenu 配置界面

> 需要安装了 ModMenu 才能访问。

### 导航结构

```
ModMenu → 哈比列车任务API → [配置]
  └─ 模式选择 (4 个卡片)
       ├─ 🔪 谋杀模式 → 任务列表 → 任务详细编辑
       ├─ 🔧 修机模式 → 任务列表 → 任务详细编辑
       ├─ ⭐ 通用任务 → 任务列表 → 任务详细编辑
       └─ 📦 自定义任务 → 任务列表 → 任务详细编辑
```

### 模式选择主界面

以 2×2 卡片网格展示四个模式，每个卡片显示：
- 图标 + 模式名称
- 任务数量、启用比例（含进度条）
- 外部 DLC 任务标记 ✦
- 支持搜索框过滤任务名称/ID/模组来源

### 任务列表界面

点击任一模式卡片进入任务列表，每行显示：
- **左侧色块**（竖条 + 方块）— 当前透视颜色
- **任务名称** — 显示名称
- **来源标签** — `[内置]` 灰色 / `[外部]` 黄色
- **启用开关** — `✔` / `✘` 快速切换
- **编辑按钮** — 进入详细配置
- 悬停时显示任务完整 ID

### 任务详细编辑

点击某任务进入，可编辑以下属性：

| 区域 | 设置项 | 说明 |
|------|--------|------|
| ⚙ 基础设置 | 启用/禁用 | 全局开关 |
| | 透视颜色 | 20 色循环预设 |
| | 描边粗细 | 1.0~10.0，步进 0.5（SRE 默认 4.0） |
| 💰 奖励设置 | 金币奖励 | 留空 = 系统默认值 |
| | 情绪奖励 | 留空 = 系统默认值 |
| | 刷新权重 | 留空 = 任务定义默认值 |
| 🗺 地图设置 | 过滤模式 | 全部地图 / 白名单 / 黑名单 |
| | 地图列表 | 逗号分隔的地图名 |

### 地图启用规则

| 过滤模式 | 地图列表 | 效果 |
|---------|---------|------|
| 全部地图 (mode=0) | 忽略 | 所有地图启用 |
| 白名单 (mode=1) | 非空 | **仅**列表中的地图启用 |
| 白名单 (mode=1) | 空 | 所有地图启用 |
| 黑名单 (mode=2) | 非空 | **排除**列表中的地图 |
| 黑名单 (mode=2) | 空 | 所有地图启用 |

### 全局设置

在模式选择界面底部点击「⚙ 全局设置」进入：

- **DLC 目标占比** — 唯一全局参数（默认 50%）
  - 范围 10%~80%，步进 5%
  - 控制 DLC 任务在全部任务中的出现频率
  - 系统根据注册数量自动计算权重乘数
  - **加新 DLC 后无需调整，自动适应**

## 4. 配置文件说明

路径：`config/habitrain_taskapi.json`

```json
{
  "global": {
    "dlcProbabilityTarget": 0.5
  },
  "tasks": {
    "habitrain_taskapi:sleep": {
      "enabled": true,
      "instinctColor": -12517376,
      "outlineWidth": 4.0
    },
    "your_mod:custom_task": {
      "enabled": true,
      "enabledMaps": ["map1", "map2"],
      "mapFilterMode": 1,
      "goldReward": 5,
      "emotionReward": 0.2,
      "refreshWeight": 1.5
    }
  }
}
```

### 每个任务的配置项

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `enabled` | bool | `true` | 是否启用 |
| `mapFilterMode` | int | `0` | 0=全局 / 1=白名单 / 2=黑名单 |
| `enabledMaps` | string[] | `[]` | 地图名列表 |
| `instinctColor` | int | `200,200,200` | 透视颜色 ARGB |
| `outlineWidth` | float | `4.0` | 透视描边粗细 |
| `goldReward` | int | `-1` | 金币奖励（-1=系统默认） |
| `emotionReward` | float | `-1.0` | 情绪奖励（-1=系统默认） |
| `refreshWeight` | float | `-1.0` | 刷新权重（-1=任务定义默认） |

> 奖励字段仅在值 ≥ 0 时写入配置文件，-1 表示使用系统默认值。

## 5. DLC 模组开发：注册自定义任务

### 5.1 添加依赖

在你的 `build.gradle` 中添加：

```groovy
repositories {
    maven { url "https://maven.terraformersmc.com/releases/" }
    flatDir { dirs "libs" }
}

dependencies {
    modImplementation files("libs/habitrain_taskapi-1.0.0.jar")
    modCompileOnly "com.terraformersmc:modmenu:11.0.3"
}
```

### 5.2 注册一个简单任务

```java
public class MyMod implements ModInitializer {
    public static final String MOD_ID = "my_mod";

    @Override
    public void onInitialize() {
        // 方式一：Lambda 快捷注册（推荐）
        HabiTaskRegistry.register(MOD_ID, "pet_cat", builder -> builder
            .displayName("撸猫")
            .category(HabiTaskCategory.ALL)
            .weight(1.0f)
            .blockTypeId(12)
            .instinctColor(new Color(255, 200, 100, 180))
        );

        // 方式二：构建器显式注册
        HabiTaskDefinition def = new HabiTaskDefinition.Builder(MOD_ID, "collect_item")
            .displayName("收集物资")
            .category(HabiTaskCategory.REPAIR)
            .weight(1.5f)
            .build();
        HabiTaskRegistry.register(def);
    }
}
```

### 5.3 注册带回调的复杂任务

```java
HabiTaskRegistry.register(MOD_ID, "collect_wood", builder -> builder
    .displayName("收集木头")
    .category(HabiTaskCategory.MURDER)
    .weight(2.0f)
    .blockTypeId(13)
    .instinctColor(new Color(139, 69, 19, 180))
    .canDirectlyWin(false)
    // 指定方块，用于 MapScanner 透视高亮
    .scanBlockIds("minecraft:oak_log", "minecraft:birch_log")
    // 分配时给道具
    .onAssign((player, instance) -> {
        instance.setMaxProgress(5);
        player.addItem(new ItemStack(Items.STONE_AXE));
    })
    // 完成时发奖励
    .onComplete((player, instance) -> {
        player.addItem(new ItemStack(Items.APPLE, 3));
    })
    // 自定义进度检查
    .completionChecker((player, instance) ->
        instance.getProgress() >= instance.getMaxProgress()
    )
    .onTick((player, instance) -> {
        // 每 tick 检测逻辑
    })
    // 仅白天可分配
    .canAssign((player, instance) -> player.level().isDay())
);
```

### 5.4 HabiTaskCategory — 任务分类

| 枚举值 | 适用模式 | 说明 |
|--------|---------|------|
| `MURDER` | 谋杀模式 | 经典列车谋杀案 |
| `REPAIR` | 修机模式 | 修复逃脱 |
| `ALL` | 所有模式 | 通用任务 |
| `CUSTOM` | 自定义 | 由 DLC 自行控制可用性 |

### 5.5 HabiTaskDefinition.Builder — 构建器参数

| 方法 | 说明 | 默认值 |
|------|------|--------|
| `displayName(String)` | 显示名称 | 同 taskId |
| `category(HabiTaskCategory)` | 分类 | `ALL` |
| `weight(float)` | 随机权重 | `1.0` |
| `blockTypeId(int)` | 方块类型 ID（≥12 自定义） | `-1` |
| `instinctColor(Color)` | 透视颜色 | `灰(200,200,200,180)` |
| `canDirectlyWin(boolean)` | 完成即获胜 | `false` |
| `scanBlocks(Block...)` | 关联的扫描方块（直接指定） | — |
| `scanBlockIds(String...)` | 关联方块 ID（延迟解析，推荐） | — |
| `onAssign(...)` | 分配时回调 | — |
| `onComplete(...)` | 完成时回调 | — |
| `completionChecker(...)` | 完成检测函数 | — |
| `onTick(...)` | 每 tick 回调 | — |
| `canAssign(...)` | 分配条件检测 | `true` |

### 5.6 任务实例 API (HabiTaskInstance)

| 方法 | 说明 |
|------|------|
| `getFullId()` | 完整 ID `"modId:taskId"` |
| `getProgress()` / `setProgress(int)` | 当前进度 |
| `getMaxProgress()` / `setMaxProgress(int)` | 最大进度 |
| `isFulfilled()` / `setFulfilled(boolean)` | 完成状态 |

### 5.7 完整示例

```java
public class DnfTaskDLC implements ModInitializer {
    public static final String MOD_ID = "dnf";

    @Override
    public void onInitialize() {
        // 任务1：下毒食物
        HabiTaskRegistry.register(MOD_ID, "poison_food", builder -> builder
            .displayName("下毒食物")
            .category(HabiTaskCategory.MURDER)
            .weight(2.0f)
            .blockTypeId(13)
            .instinctColor(new Color(180, 0, 255, 200))
            .onAssign((player, task) -> {
                task.setMaxProgress(3);
                player.sendSystemMessage(
                    Component.literal("§5【任务】去食物盘下毒！(0/3)"));
            })
            .onTick((player, task) -> {
                // 自定义进度检测逻辑
            })
            .completionChecker((player, task) ->
                task.getProgress() >= task.getMaxProgress())
            .onComplete((player, task) -> {
                player.sendSystemMessage(
                    Component.literal("§a✔ 下毒任务完成！"));
            })
        );

        // 任务2：救赎（外部标记完成）
        HabiTaskRegistry.register(MOD_ID, "redemption", builder -> builder
            .displayName("救赎")
            .category(HabiTaskCategory.MURDER)
            .weight(1.0f)
            .completionChecker((player, task) -> task.isFulfilled())
        );
    }
}
```

## 6. 回调系统详解

### 生命周期

```
onAssign(player, task)    ← 任务分配给玩家
  │
  ▼
每游戏刻:
  ├─ onTick(player, task)           ← 进度更新逻辑
  └─ completionChecker(player, task) ← 检测是否完成
       └─ 返回 true →
            ├─ setFulfilled(true)
            ├─ onComplete(player, task)        ← 完成回调
            ├─ handleTaskCompletion()
            │    ├─ 发放配置奖励（金币/情绪）
            │    └─ 如 canDirectlyWin → 触发直接获胜
            └─ 移除任务
```

### 各回调用途

| 回调 | 频率 | 用途 | 性能注意 |
|------|------|------|---------|
| `onAssign` | 1 次/任务 | 给起始道具、设进度上限、发提示 | 可较重 |
| `onTick` | 20 次/秒 | 检测玩家位置/物品/周围方块 | **保持轻量** |
| `completionChecker` | 20 次/秒 | 检测任务是否完成 | **保持轻量** |
| `onComplete` | 1 次/任务 | 发放奖励、触发效果、传送 | 可较重 |
| `canAssign` | 每次生成 | 控制谁可以接到此任务 | 保持轻量 |

### 奖励分层

任务完成后的奖励分两层，互不冲突：

```
DLC 自定义奖励 ← onComplete() 回调中自行发放
框架配置奖励 ← ModMenu 配置的金币/情绪，框架自动发放
直接获胜     ← canDirectlyWin(true)，框架自动触发
```

## 7. 方块透视与扫描

### 两种方式

| 方式 | 说明 | 推荐场景 |
|------|------|---------|
| **`scanBlockIds`** | 指定方块 ID 字符串，扫描时延迟解析 | 大多数情况，推荐 |
| **`scanBlocks`** | 直接指定 Block 对象 | 方块在注册时已加载 |
| **`TaskInstinctShowableInterface`** | 实现 SRE 接口，每方块独立控制 | 需精细控制（如仅特定玩家可见） |

### blockTypeId 分配规则

| 范围 | 用途 | 说明 |
|------|------|------|
| 1~11 | SRE 原版保留 | 请勿使用 |
| **12+** | **DLC 自定义任务** | 每个任务使用唯一 ID |
| -1 | 无关联方块 | 纯逻辑任务 |

> ⚠️ 每个 `blockTypeId` 只对应一种透视颜色，不同任务使用相同 ID 会共享颜色。建议 DLC 之间协调分配。

### 使用示例

```java
// 推荐：使用方块 ID 字符串（延迟解析，兼容跨模组加载顺序）
.scanBlockIds("minecraft:oak_log", "minecraft:birch_log")

// 或称：直接指定 Block 对象
.scanBlocks(Blocks.IRON_ORE, MyBlocks.CUSTOM_BLOCK)
```

### 渲染行为

| 模式 | 行为 |
|------|------|
| 旁观/创造 | 渲染所有自定义任务方块（类型 ≥12） |
| 生存 | 仅渲染玩家当前活跃的 DLC 任务匹配方块 |
| 颜色 | 优先使用 ModMenu 配置色 → 任务定义默认色 |
| 描边粗细 | 从 ModMenu 配置读取（默认 4.0） |

## 8. 自动平衡系统

这是本 API 的核心机制，每次构建任务池时**实时计算**权重乘数，无需手动配置。

### 工作原理

```
autoBoost = target / (1 - target) × 可用原版任务数 / 可用DLC任务数
```

**流程：**
1. 原版任务加入权重池（含情绪/历史次数权重调整）
2. 统计实际进入池的原版任务数
3. 统计可用的 DLC 任务数（经地图禁用、分类匹配、`canAssign` 过滤后）
4. 自动计算 `autoBoost`，使 DLC 集体概率 = 目标比例
5. DLC 任务以 ×autoBoost 的权重加入同一池
6. 加权随机选择

### 特性

- ✅ **加新 DLC 模组** → 自动适应，无需修改配置
- ✅ **地图禁用某些任务** → 自动从池中排除，不影响平衡
- ✅ **原版任务情绪/次数权重** → 不受影响，保留原汁原味
- ✅ **分类回退** — DLC 任务获取时使用 4 级回退匹配（精确分类 → MURDER → ALL → 忽略分类），避免任务因模式切换无法出现
- ✅ **防止覆盖** — 玩家已有活跃 DLC 任务时，不再将 DLC 任务加入池

## 9. 常见问题与调试

### Q: ModMenu 中没有配置按钮？
确保安装了 ModMenu ≥11.0.3，且 `habitrain_taskapi` 出现在 ModMenu 列表。

### Q: 自定义任务没有透视效果？
- `blockTypeId` 是否 ≥12？
- 是否使用了 `scanBlocks`/`scanBlockIds` 指明了关联方块？
- 客户端是否安装了本模组？
- 任务在当前地图是否启用？

### Q: 任务不生成？
按以下顺序排查：
1. 任务是否启用？
2. 当前地图是否在启用/禁用列表中？
3. 分类是否匹配游戏模式？
4. `canAssign` 是否返回 `true`？
5. 权重是否 > 0？
6. 玩家是否已有同类任务（不会重复分配）？

### Q: 如何调试？
在 JVM 参数中加入：
```
-Dfabric.log.level=com.habitrain.taskapi=DEBUG
```
日志输出 `[HabiDebug]` 前缀的详细信息。

### Q: 与 SRE 原版任务冲突吗？
不会。原版任务被注册为内置任务，通过同一个 Mixin 统一管理。配置页面中可以单独控制原版任务。原版的 `getDisabledTasks()` 和地图禁用仍然有效。

### Q: 为什么内置任务有 `raed_book`？
SRE 原版 `Task` 枚举中拼写为 `RAED_BOOK`（拼写错误）。为兼容，本 API 保留了此 ID。

### Q: 如何让任务只给特定角色？
使用 `canAssign`：
```java
.canAssign((player, task) -> {
    var role = SREComponents.ROLE.maybeGet(player);
    return role.isPresent() && role.get().getRoleName().equals("Murderer");
})
```
