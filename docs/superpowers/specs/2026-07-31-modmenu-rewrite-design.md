# ModMenu 配置界面重写设计（2026-07-31）

## 背景与目标

`habitrain_core`（哈比列车核心）现有 ModMenu 配置界面由顶部 6 Tab 构成，约 5600 行 GUI 代码（`client/gui/config/` 11 类 + `client/gui/` 编辑器类）。Mike 要求**从 0 重写整个 ModMenu 界面**，条件：

1. 保留原有全部功能（功能等价）。
2. 功能分类完整、符合直觉。
3. 每个可修改选项的页面下方都要有保存按钮。

**已确认的三个关键决策：**

- **范围**：全部 GUI 重写；底层配置模型（`ConfigManager`/`ConfigRepository`/`ConfigStore`/`ConfigSync`/`MinigameEnforcement`/`EnvProfile` 等）与数据模型完全复用，不改动。
- **保存语义**：改即生效 + 手动保存（改动最小）。开关/滑块/循环按钮修改后仍立即生效（与旧版一致）；每页底部新增「保存」按钮，点击才真正写入配置文件并同步服务器；关闭面板时仍自动保存（兼容旧行为）。
- **分类结构**：按系统域重新设计——左侧分类树 + 右侧内容区 + 底部保存栏。

## 一、总体架构与导航

### 布局

```
├──────────┬──────────────────────────────────────────────┤

│ ▸ 对局流程│                                              │

│ ▸ 系统    │                                              │
├──────────┴──────────────────────────────────────────────┤
│ ● 有未保存的修改                        [保存]  [返回]    │

```

- 左侧 5 个可折叠分类：任务中心 / 对局流程 / 环境 / 角色 / 系统。分类下是具体页面，点击切换右侧内容区。
- 视觉语言完全沿用旧版：深色背景、分类强调色、行背景、滚动条、20 色任务调色板、中文标签。

### 架构：单 Screen + 页面栈

- 所有配置界面统一进**一个** `ConfigRootScreen`。
- 页面实现统一 `ConfigPage` 接口（`render / mouseClicked / mouseDragged / mouseReleased / mouseScrolled / keyPressed / charTyped / onEnter / onLeave`）。
- 子编辑器（任务详情、小游戏详情）也做成**页面压栈**：顶部面包屑「任务中心 > 内置任务 > 任务详情」，不再单独 `setScreen` 切换。
- 底部固定保存栏：`● 有未保存的修改` 指示器（有改动未落盘时点亮）+「保存」+「返回」。
- 只读模式（联机非 OP）：所有控件禁用 + 底部提示，沿用 `LiveConfigAccess` 语义。

## 二、各页面内容映射

所有页面保留旧版全部功能与交互，改动仅体现在重新归组与底部保存栏。

### 任务中心

**1. 内置任务**（旧 TaskTab 去掉停电/小游戏后的部分）
- 左侧搜索框 + 任务列表（基础/谋杀/修机/通用/自定义分组，含每类已启用数），右侧任务网格（启用状态、颜色条、编辑按钮）。
- 编辑 → 压栈打开任务详情页（旧 TaskEditScreen）：基础设置（启用/instinct 颜色/描边宽度）+ 奖励设置（金/情感/权重，空=默认）+ 地图设置（全部/白名单/黑名单 + 地图列表）+ 基本信息只读 + 保存/保存并返回/重置默认。
- 保存栏：任务详情页内点「保存修改」写任务项（markDirty），底部「保存」落盘。

**2. 停电任务**（旧 TaskTab 中 `habitrain:blackout` 好人/坏人两组）
- 好人任务（绿色强调）与坏人任务（红色强调）分区，每行启用状态、颜色条、编辑按钮，编辑复用任务详情页（额外显示停电商店售价字段，仅停电任务可见）。

**3. 扩展任务**（DLC 任务）
- 与内置任务同结构，单独一页，避免混在长列表里。

**4. 小游戏**（旧 MinigameTab）
- 搜索 + 卡片网格（颜色条/名称/ID/奖励预览/启用开关/编辑），编辑 → 小游戏详情页（旧 MinigameEditScreen，无商店价）。未检测到 SRE 时整页显示不可用提示。

**5. 任务全局参数**（旧 GlobalTab 里的 DLC 概率滑块 + 小游戏总开关）
- DLC 目标占比滑块（10%~80%，步长 5%）+ 小游戏任务总开关。

### 对局流程

**6. 投票设置**（旧 VoteTab，时长/模式地图候选/顺序调整/skip）
- 总开关、模式投票时长/地图投票时长、可投票模式列表（启用/名称/可选地图/上下移）、可投票地图列表（启用/名称）、请求跳过当前池按钮。
- 数字输入与名称编辑框在点「保存」或离开页面时提交（保留旧 flush 逻辑）；模式顺序调整等开关类仍立即生效。
- 地图池轮换从投票页拆到独立页。

**7. 地图池轮换**（旧 MapPoolEditorScreen）
- 左侧池列表（1~20 池，名称/启用/当前池标记），右侧该池地图多选；「+添加池」「删本池」「重新均摊分池」「清空本池」。
- 所有改动在内存，点底部「保存」才写入并落盘；「返回不保存即丢弃」行为保留。

**8. 全局玩法参数**（旧 GlobalTab 其余部分）
- 警长数量除数（输入+应用）、临时电源价格（输入+应用）、杀手刀耐久开关。

### 环境

**9-12. 大厅环境 / 对局环境 / 局后时间 / 动态雨**
- 旧 EnvironmentTab 的四个子页提升为四个独立页面，左侧分类树各占一项。内容与交互完全保留：环境覆盖开关、时间预设/刻、天气、雪/沙/雾、fogEnd、昼夜循环、对局地图覆盖列表与删除、好人/杀手局后时间、低人数动态雨阈值。

### 角色

**13. 角色覆盖**（旧 RoleOverrideTab）
- 总开关 + 条目列表（状态/替换或调整标签/名称/来源/目标角色/描述/冲突与无效状态高亮），点行自动禁用同目标其他条目。每个开关点后仍立即保存（旧版行为，角色覆盖重建依赖落盘）。

### 系统

**14. 光影白名单**（旧 ShaderWhitelistScreen 提升为页面）
- 白名单总开关 + 添加框/添加按钮 + 列表（悬停删除），逐条修改仍立即生效。

### 页面级保存按钮总结

| 页面 | 底部保存按钮效果 |
|---|---|
| 任务详情 / 小游戏详情 | 提交输入框 + 写任务项（等同旧「保存修改」） |
| 地图池轮换 | 提交池名称/地图选择 → 写入并落盘（等同旧「保存」） |
| 投票设置 | 提交时长/名称输入 → 写入并落盘（等同旧「保存」） |
| 其余所有页面 | `ConfigManager.save()` 落盘 + 同步服务器 + 清未保存标记 |

关闭面板时仍自动保存（兼容旧行为）；「有未保存修改」指示器在有改动未落盘时点亮。

## 三、共享基建与实现细节

### 代码组织

**复用不动：** `SharedGuiKit`（颜色/背景/滚动条/命中测试）、`SharedGuiConstants`（20 色任务调色板）、`LiveConfigAccess`（权限）。

**删除旧 GUI：** `client/gui/config/` 下 11 个旧类（ConfigRootScreen、TaskTab、MinigameTab、GlobalTab、VoteTab、EnvironmentTab、RoleOverrideTab、MapPoolEditor、MinigameEdit、ModeAllowedMaps）+ `client/gui/` 下 `TaskEditScreen`、`ShaderWhitelistScreen`、`TaskColorPicker`、`TaskSaveController`、`TaskMapFilterEditor`。

**新建**（仍放 `client/gui/config/` 包）：
- `ConfigRootScreen` — 新根：左侧分类树 + 内容区 + 底部保存栏 + 页面栈。
- `ConfigPage` 接口 — 统一页面契约。
- 14 个页面类 + 任务详情/小游戏详情两个子页面（页面压栈，不 `setScreen`）。
- `widget/` 子包 — 通用控件：`ToggleButton`、`NumberField`+`ApplyButton`、`SliderRow`、`ColorCyclePicker`、`MapFilterField`、`ScrollPane`。
- `SaveBar` — 底部保存栏组件。

`ModMenuIntegration` 仍返回 `ConfigRootScreen::new`；`ConfigRootScreen.openVote(parent)` 彩票桥入口保留。

### 页面栈与事件

- 根界面维护 `Stack<Page>`。子页面入栈后事件先派发给栈顶页面；顶部面包屑显示路径；「返回」= 出栈回上一页；根返回 = 回 ModMenu 父界面。
- `ConfigPage.onEnter/onLeave`：切页/出栈时刷未提交输入（等价旧 `flushPendingFields`/`flushFocusedFields`）。

### 底部保存栏与未保存标记

- 保存栏固定渲染在根界面底部：`● 有未保存的修改`（仅 dirty 点亮）+「保存」+「返回」。
- **dirty 追踪**：所有改配置的操作调 `root.markDirty()`；「保存」调用当前页面 `applyPendingFields()`（若有输入框）→ `ConfigManager.save()` → 清标记。旧版里点按钮立即调 `save()` 的页面（角色覆盖、投票/地图池顺序调整等）为保留行为，仍直接 `save()` 并顺带清标记。
- 关闭面板仍自动保存（兼容旧行为）。

### 滚动与输入统一

- 所有页面用 `ScrollPane` 统一滚动：滚轮 + 拖拽 + 统一滚动条。
- **修复**旧版「拖拽/滚轮上限 10000 与滚动条实际高度不一致」的 quirk（滚动条拇指越界），按真实内容高度夹紧。
- `mouseReleased` 统一转发给所有页面（旧版只转给 3 个页，任务/小游戏页拖拽标记不释放）。

### 只读模式

- 联机非 OP：所有控件禁用（按钮 `active=false`、输入框不可编辑）、操作弹拒绝提示、底部显示只读提示——沿用旧 `LiveConfigAccess` 语义。

### 构建与验证

- 按项目协议：`./gradlew clean build` → 复制唯一主 JAR 到 `D:\Backup\mc mod\临时\` → 核对名称/字节数/SHA-256。
- 更新 `mod-architecture.md` 第 11 节（Tab 类名列表）与 `maintenance-log.md`。
- 游戏内验证清单（需 Mike 运行客户端检查）：每个页面开关、保存按钮、只读模式、子页面进出、投票 flush、地图池保存等。

## 风险与边界

- **依赖保持**：重写不触碰 `ConfigManager` 公开 API 与数据模型，服务端同步、持久化、权限、角色覆盖重建链路不受影响。
- **行为等价基准**：以旧版功能清单为基准（任务/小游戏启用即时生效、投票 flush、地图池内存编辑、环境字段应用按钮、角色覆盖即时落盘、光影白名单即时生效）。
- **已知 quirk**：滚动上限不一致、`mouseReleased` 未全转发——本次一并修复（视觉不变，属有意行为修正）。
