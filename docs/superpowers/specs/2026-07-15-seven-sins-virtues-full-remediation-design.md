# 七宗罪与七美德完整修复设计

日期：2026-07-15  
目标项目：`D:\Backup\mc mod\哈比列车api`  
目标平台：Fabric 1.21.1 / Java 21 / SRE 4.3.0

## 1. 目标与边界

本次修复以 Mike 已确认的七宗罪、七美德设计稿为唯一行为规格，替换当前代码中所有已确认的 MVP、近似实现和错误判定。修改范围限定在 `habitrain_core`；不修改 DLC 源码，不改动无关的停电模式、任务 UI 和其他角色逻辑。

所有技能、交易、死亡许可、胜利和状态变化由服务端决定。客户端仅提交输入意图并显示界面、高亮、滤镜和提示。客户端提供的玩家 UUID、物品、价格、确认状态和阶段不得作为可信事实。

## 2. 公共基础设施

### 2.1 阵营判定

新增统一的角色阵营判定工具，明确区分好人、杀手、杀手共享中立和独立中立。暴怒阶段和宽容只接受真实好人阵营攻击者，不再使用 `!canUseKiller()` 作为好人判定。

### 2.2 服务端目标选择

傲慢复制、嫉妒标记和贪婪交易统一使用服务端射线选择器。客户端 UUID 只能作为命中提示；服务端必须重新验证同维度、存活、非旁观、最大距离、准星夹角和无遮挡视线。验证失败时技能不进入冷却。

### 2.3 死亡原因分类

常规武器、毒类、特殊强制死亡使用完整的 `ResourceLocation` 集合，并优先引用 SRE `GameConstants.DeathReasons`。不使用模糊字符串包含判断。傲慢、暴怒和懒惰共享同一常规武器分类，避免同一武器在三个角色中表现不一致。

### 2.4 七宗罪互斥

七宗罪继续保持两两互斥和 `defaultMax=1`。最终角色确认阶段若仍出现多个七宗罪，保留一个并按被移除角色原本占用的阵营位置选择同阵营后备角色，不能把中立或警长位置无条件改成平民。

## 3. 七宗罪修复

### 3.1 傲慢

- 复制商店只保存目标角色 ID 和基础价格快照。
- 重建条目时保留原始条目的 `canDisplay`、`canBuy`、`onBuy`、货币类型和商品行为，只覆盖基础价格；动态价格、个人折扣、余额和购买记录不复制。
- 8 格内其他存活玩家达到 3 人时发光并获得完整登记的常规武器免疫；击杀后强制破防 5 秒。
- 好人/杀手阵营结束判定在傲慢仍存活且有其他存活者时被阻止；傲慢成为唯一存活者时触发独立胜利。

### 3.2 嫉妒

- 开启透视，关闭时间显示。
- 标记目标必须通过服务端射线。
- 只限制当前标记目标；余额比较在死亡许可时重新读取。
- 击杀标记目标后只移动一个合法物品单位，保留该物品完整数据；钥匙、任务物品、职业绑定、灵魂绑定和明确不可转移物品不得进入候选池。
- 无合法物品时原子转移最多 100 金币。

### 3.3 暴怒

- 只有明确好人阵营造成的已登记常规武器致死攻击推进阶段；拳头、环境、特殊死亡不推进。
- 第一阶段使用服务端位置锚定实现 3 秒禁锢；阶段结束后释放。
- 红色、黑白和迷幻效果通过专属客户端视觉状态实现；黑暗、失明等游戏效果仍由服务端维持，普通净化后会被重施。
- 每次击杀降低当前愤怒阶段一级；进入失智后的累计击杀数独立保存，达到 5 时强制死亡。

### 3.4 贪婪

- 收纳袋继续使用绑定 UUID，但袋内保存真实 `ItemStack` 内容，而不是只保存 ID 集合。
- 收集进度按袋内不同物品 ID 计算，忽略数量、耐久和 NBT；放入袋中的物品保持原始数据。
- 禁止主动丢弃和交易收纳袋；任何非授权转移导致所有者立即强制死亡。
- 开局目标固定为 `ceil(开局人数 × 2.5)`。
- 在背包/受限背包界面提供交易入口和玩家选择界面。双方进入独立交易确认界面，只显示交易方向、真实物品、价格和确认状态；对方身份对非发起者保持匿名。
- 服务端会话记录双方 UUID、物品槽位/指纹、报价和确认状态。双方确认后在服务器线程重新校验袋归属、实际物品、余额、存活状态和价格，再以可回滚顺序提交。
- 每个物品 ID 的全局成交次数限制在 0 至 3；达到 3 后价格固定，但仍允许继续交易。
- 出售从袋中取出真实物品，收购把对方的真实物品移入袋中，不生成默认物品替代。

### 3.5 暴食

- 开启完整可食用物品商店，奶桶和蜂蜜使用指定价格。
- 每种正面效果拥有独立最高等级；重复抽取达到该效果上限后，再抽取一次才变为本局永久。
- 食物奖励只在服务端确认物品完成食用并实际消耗后触发。
- 普通负面效果使用明确白名单在施加入口阻止，并在 tick 中兜底清除；角色机制、槟榔、诅咒、专属滤镜和特殊死亡效果不清除。

### 3.6 色欲

- 色欲只有在本局能够并确实生成一对互相绑定的真正恋人时保留；否则在最终确认阶段替换为同阵营后备角色。
- 色欲自身不获得恋人修饰符。
- 一阶段只向色欲客户端同步真正恋人 UUID。两名恋人同时处于 8 格、存活且无遮挡时，持续观察累计能量；条件中断时暂停。
- 二阶段欲望标记只写入独立组件，不调用原版恋人配对、殉情或胜利逻辑。
- 真正恋人胜利时，若色欲仍存活，则把自定义胜者列表替换为色欲。

### 3.7 懒惰

- 沉睡开始时保存位置与朝向。服务端拒绝移动/跳跃并持续校正到锚点；客户端拦截移动、攻击、使用、交互、背包/界面打开和文字输入。
- 服务端仍对攻击、交互、容器和聊天入口做硬性校验；语音插件继续取消麦克风包。
- 护盾在统一攻击/死亡入口扣除并记录攻击者。护盾破裂后只允许攻击本轮攻击者，客户端高亮这些 UUID。
- 主动苏醒消耗全部护盾，触发不会伤害自身的护盾爆炸，并进入 30 秒开放狂暴。
- 任何狂暴阶段每击杀 2 人获得 1 护盾；结束后至少以 1 护盾重新沉睡并清空攻击者集合。
- 仅好人或杀手阵营胜利会被存活懒惰替换；`TIME` 和其他自定义结局不被劫持。

## 4. 七美德修复

- 七美德仍使用 `SREModifier`；每名玩家最终只保留一个七美德，慷慨只关联现有实例。
- 谦卑覆盖 SRE 和 HabiTrain 的真实任务完成入口，仅在附近显示“谢谢”。
- 宽容只生成于好人阵营，并且只抵消第一次来自真实好人阵营的击杀。
- 耐心和勤勉通过统一的“有效交互时长”接口处理 SRE 与 API/DLC 任务；纯等待、自动完成、点击计数、进食和场景触发不缩放。
- 节制按玩家和具体商店条目标识记录折扣。折扣基于该条目的原始价格序列计算，再与动态商店价格组合一次；不会把已经应用动态倍率的付款价再次乘动态倍率。
- 贞洁使用明确登记的毒效果和毒死亡原因集合，不以命名空间或模糊名称替代登记；槟榔、迷幻、诅咒和职业效果默认不在集合内。

## 5. 客户端表现与网络

新增或扩展客户端状态同步以支持暴怒滤镜、色欲恋人/欲望高亮、懒惰攻击者高亮和沉睡输入锁。同步包只包含显示所需的阶段、时间和 UUID 集合，不同步隐藏角色身份或服务端经济数据。

所有 C2S 包限制字符串长度、枚举值和会话 UUID，并在服务器线程执行。重复确认、过期会话、断线、死亡、换维度、价格变化或物品变化都会关闭交易且不产生部分提交。
