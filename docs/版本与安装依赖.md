# 版本与安装依赖

## 版本来源

当前产物版本以 [gradle.properties](../gradle.properties) 的 `mod_version` 为唯一来源；运行时读取 `CoreApi.modVersion()`。公开 API 与角色 API 版本分别来自 [CoreApi](../src/main/java/com/habitrain/core/api/CoreApi.java) 的常量，当前为 `2.2` / `2.0`，并由测试核对 [fabric.mod.json](../src/main/resources/fabric.mod.json) 的 custom 段。旧教程里的 2.0.11 依赖片段与历史变更章节描述当时版本，不代表当前安装清单。

固定环境：Minecraft 1.21.1、Java 21 或更新且可运行 Java 21 字节码的版本、Fabric Loader 0.18.2、Fabric API 0.116.13+1.21.1。用户安装必须使用 `libs/star_rail_express-4.3.0.jar`；`-dev.jar` 仅用于当前开发构建。固定 SRE 成品 SHA-256：`081d4598a675be74a1351ad4c68602c1f80936f32f87352eee52c418e6906b21`。

## 需要安装的外部模组

下表按项目固定成品及缓存中的**原始发行 JAR**元数据核对。缓存 `remapped_mods` 与 `-sources.jar` 不可当作发行模组安装。除 Core 的 playerAnimator 外，不应假定 Core 会把开发运行依赖一起打包。

| StarRailExpress / `starrailexpress` | 4.3.0 固定成品 | Core | `libs/star_rail_express-4.3.0.jar` |
| DataSync / `datasync_minecraft` | 0.10.2 | Core 明确要求；固定 SRE 运行类也使用它 | 另装该版本；已有 Ratatouille 1.4.3 的嵌套 0.10.2 可满足，无需重复 |
| CCA / `cardinal-components-base` | 6.1.3 | Core | 另装 |
| CCA / `cardinal-components-entity` | 6.1.3 | Core | 另装 |
| CCA / `cardinal-components-world` | 6.1.3 | Core | 另装 |

## 专用服限制与启动验收

固定 SRE 4.3.0 在 `environment="*"` 下声明 `depends.modmenu="*"`，固定 Mod Menu 11.0.3 却是 `environment="client"`。按服务端环境过滤后的依赖 ID 闭包缺 `starrailexpress -> modmenu`。将客户端 Mod Menu JAR 放进服务器目录不能据此宣称已经满足服务端依赖。此上游成品不可修改；部署方需要上游认可的专用服方案，并用真实 Fabric Loader 验证。不得在 Core 修复中静默改写上游 JAR 或自动绕过其依赖声明。

开发入口为项目 wrapper：

```powershell
.\gradlew.bat runClient --no-daemon
.\gradlew.bat runServer --no-daemon
```

开发入口使用 `-dev.jar`，不能替代固定成品验收。成品验收需在工作区内的干净实例中装 Fabric Loader 0.18.2、上表原始成品与新 Core，分别启动客户端/专用服，检查依赖解析、required Mixin 与关键入口。用户 EULA 与账号登录应由实例所有者处理。每个一次性启动结束后须检查其 Java 子进程退出；客户端和服务器游戏交互结果另行记录，未执行不得写为通过。

本次本页记录的是静态依赖核对；真实启动和多人场景的状态以 [运行验收清单](运行验收清单.md) 及交付记录为准。
